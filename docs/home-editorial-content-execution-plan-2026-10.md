## 1. 要解决的问题与交付结果

管理员更换首页主推视频时，应当在后台完成：

**选视频 → AI 生成内容草稿 → 编辑与预览 → 发布到指定位置 → 必要时恢复上一版。**

日常换内容不改前端代码、不重新部署，也不要求管理员手写整页。LLM 在管理员制作内容时调用，用户打开首页、点击选项、收词时不调用 LLM。

交付必须包括数据库、后端、后台编辑界面和真实首页接入，不能只完成 API 或留下静态示例。先打通维护闭环，再接入已讨论的首页视觉和轻互动。

本次交接只授权后续 agent 实施本地开发与验证，不包含生产部署。执行前重读根、backend、frontend 的 CLAUDE.md；本文中现状以本次实际读到的代码为依据，路径与接口在实施时复核。

## 2. 视觉与产品边界

**2026-10-20 最终视觉修正：** 用户已用紧凑方案替代最初的主次双列设计。首页为「今日精选」标题与紧凑按钮组 → 单个通用视频横卡 → 本期关联「今天就能用」 → 视频列表。教学细节默认收起。次推保留服务端递补用途，独立表达位不再渲染；既有发布/回退契约不改。普通精选无需 LLM 文案即可使用相同横卡。场景只跟随当前主推版本并有字幕依据；同版本编排可排序，跨视频/旧版本场景不会混入。未制作场景时用该视频真实字幕练一句，缺字幕则隐藏，不再补通用例句。以下维护系统设计保留；展示结构以本段及实施文档 §6 为准。验收需覆盖真实数据与编排内容的桌面/手机截图，以及视频列表出现的高度。

采用此前预览中的「好奇心优先」方向：内容为主，一条主要互动；继续学习和少量复习作为轻入口。「接着你来」作为后续回访用户方案，本期不做两版切换器或自动人群分流。

## 4. 实现选择

### 4.1 内容包与首页位置分开

视频的编辑内容可以复用；首页配置负责决定展示哪个版本、放在哪里。不要将内容直接写进 React 文件，也不要为了换主推去修改视频创建时间。

建议最小数据结构为三张表，名称可按仓库习惯调整，以下语义不可省略：

1. `home_content_drafts`：每视频一份可编辑草稿。
   - `video_id` 唯一；`payload` 为经 Pydantic 校验的 JSON；`schema_version`。
   - `revision` 用于乐观锁；`source_fingerprint` 为生成或编辑依据的字幕版本指纹。
   - 生成状态：`idle / queued / running / succeeded / failed`，另存 `active_generation_id`、任务开始/完成时间、错误码、简短错误说明。
   - 保存生成时的草稿 revision、模型、prompt 版本、操作者与时间。
2. `home_content_revisions`：不可变的已发布内容版本。
   - `id`、`video_id`、版本号、完整 payload、来源指纹、生成信息、发布人、发布时间。
   - 发布产生新记录；不原地修改历史版本。可从历史版本复制回草稿。
3. `home_page_config`：首页单例配置。
   - `draft_layout`、`published_layout`、`previous_published_layout`、`revision`、更新信息。
   - layout 保存位置与 `content_revision_id`，表达卡另带稳定的 `expression_id / scenario_id`。
   - 只引用已发布的不可变版本。因此重新生成或编辑草稿不会影响线上内容。

示意 layout：

```json
{
  "lead": {"content_revision_id": "..."},
  "secondary": [{"content_revision_id": "..."}],
  "expression": {"content_revision_id": "...", "expression_id": "..."},
  "scenarios": [{"content_revision_id": "...", "scenario_id": "..."}]
}
```

后台应提供快捷操作「发布并替换主推」，在一个数据库事务中创建不可变版本并替换对应首页位置。不要让管理员必须理解三张表才能换视频。页面整体发布与恢复上一版也应原子完成。

恢复上一版必须重新检查来源、视频可见性和可播放性，不能恢复已下线的视频。事务成功后再清缓存。

### 4.2 草稿内容契约

定义专用 Pydantic schema 与对应前端类型，禁止前端直接解释任意 JSON。

| 字段 | 约束与用途 |
| --- | --- |
| `headline` | 中文编辑标题，建议不超过 32 字，避免夸大和与内容无关的悬念 |
| `dek` | 一两句推荐理由，建议不超过 80 字，说清话题及英语收获 |
| `topic_label` | 短主题标签；难度、全片时长、来源不由 LLM 生成 |
| `evidence_subtitle_ids` | 标题与导语的主要依据，必须属于当前视频；方便管理员对照原文 |
| `clip` | 连续片段的起始/结束字幕 ID，由服务端解析并校验时间；不接受模型编造时间 |
| `expressions` | 1–3 条，包含稳定 ID、真实原句对应的字幕 ID、选中的词或短语、中文教学说明 |
| `interaction` | 可空；一个问题、2–3 个稳定 ID 选项、每选项一段反馈；没有正确答案字段 |
| `scenarios` | 0–3 条，稳定 ID、真实表达引用、中文情境、提示、英语参考回复与译文 |

标题等长度与列表数量应由 schema 约束；标识符重复、引用不属于视频、时间颠倒等为校验错误。草稿允许不完整保存，但发布校验必须严格。

英语原文、中文字幕、时间、封面、视频总时长直接读真实数据。模型可以选字幕 ID 和表达，不能重写原句后冒充引用。词义与音标优先沿用现有词典；缺失时不伪造。

场景参考回复属于生成的教学例句，应显示「参考表达」；不要标成视频原话。英语句子必须可直接作为现有收词/跟读入口的真实上下文时，才显示对应操作；新造例句不伪造字幕 ID。

片段目标长度可设为 30–120 秒，但不是强制凑时长；短视频或无合适片段时允许更短。按钮按真实时长显示，不能固定写「90 秒」。没有本地可播放媒体时不展示站内片段试听按钮，可退回完整视频入口。

### 4.3 输入与生成

1. 管理员选定一条已完成字幕处理的视频并点「生成草稿」。允许提前制作未公开视频，正式发布时必须满足公共可见条件。
2. 服务端按顺序读取字幕、译文、字幕 ID 与已存在的视频事实，计算来源指纹。字幕作为不可信资料输入，明确要求模型不能执行其中的指令。
3. 调用现有 `AIService.chat_json()` 获取结构化内容。不要新建独立供应商 SDK 或硬编码模型。
4. 普通长度视频可一次输入全文；超出输入预算时先按原字幕边界分段筛候选，再从候选生成最终草稿。限制输入和调用次数，并记录未覆盖范围；禁止只截前几分钟却声称基于全文精选。
5. Pydantic 校验加来源校验：字幕归属、原句与表达是否确实存在、片段时间合法、问题/反馈结构完整。不要另开一个自由文本响应后靠正则猜结构。
6. 合法结果写回草稿；后台呈现结果、依据字幕和可播放片段。

调用次数、prompt 版本与生成时间可追踪；若现有服务能返回 usage 则记录实际值，否则显示不可用，不估算成真实消费。失败不能伪装成功。

LLM 本次只辅助编辑：不自动发布、不在用户点击选项时生成反馈、不自动改用户学习记录。管理员可以完全手写维护，模型未配置或暂不可用不能锁死编辑与发布。

### 4.4 任务并发与草稿保护

- 生成走现有云端 Celery，不阻塞 HTTP 请求；前端显示可轮询的状态。
- 同一视频同一时刻只允许一个有效生成任务。重复点击返回既有任务，避免重复计费；锁与状态更新不能只有前端 disabled。
- worker 写回时比较 generation ID、生成前的 draft revision、来源指纹。任何一项不匹配，都不能覆盖管理员新修改的内容；返回明确冲突状态或失败原因，允许重新生成。
- 已存在草稿时，重新生成之前给出明确的覆盖提示；先保留现有草稿，结果成功且未发生冲突后才替换。已发布版本始终不变。
- worker 失败、超时或入队失败必须可见、可重试；不得永久卡在 generating。设置任务期限，并在状态读取或既有巡检机制中处理超时任务。
- 手动保存、发布、首页布局修改都携带 expected revision；冲突返回 409，提示重新加载，不使用最后写入者静默覆盖。

## 5. 后台操作界面

视频详情增加「首页内容」区域：

- 状态：未制作 / 草稿 / 已发布版本 / 来源已变更；生成任务状态单独显示。
- 操作：生成草稿、重新生成、保存、预览、发布到主推或次推、复制历史版本为草稿。
- 编辑：标题、推荐理由、选词/表达、片段、问题、选项反馈、场景。
- 片段通过字幕列表选择起止，可试听；引用内容可一键定位查看原文。
- 预览复用首页展示组件，防止后台看着一套、首页变成另一套。

再增加轻量「首页编排」页面：

- 选择主推 1 条、次推最多 2 条和可选的表达/场景卡，明确展示位置，支持替换和顺序调整。
- 只能选已发布且来源有效的内容版本；主次视频不重复。草稿视频可先完成发布再进入布局。
- 保存布局草稿、整体预览、发布、恢复上一版。
- 删除已使用的表达或场景 ID、选择下线视频等在发布时给出字段级错误，不能静默丢内容。

保留原「首页展示」作为旧精选的候选池开关。在新界面中说明其用途，避免它与新编排都叫“主推”。自动精选 `is_featured` 不参与新位置决策。

## 6. 建议接口边界

路由名可微调，保持领域行为与鉴权边界；API 路由只做解析与调用，逻辑收敛在 service。

| 接口（新增建议） | 用途 |
| --- | --- |
| `GET /api/v1/admin/home-content/videos/{video_id}` | 草稿、revision、任务状态、版本列表；管理员鉴权 |
| `POST /api/v1/admin/home-content/videos/{video_id}/generate` | 入队，返回 202 和 generation ID；支持 expected revision |
| `PUT /api/v1/admin/home-content/videos/{video_id}/draft` | 保存草稿，乐观锁 |
| `POST /api/v1/admin/home-content/videos/{video_id}/publish` | 校验并创建不可变版本；可带目标位置在同事务内替换 |
| `POST /api/v1/admin/home-content/videos/{video_id}/restore-draft` | 指定历史版本复制为新草稿 |
| `GET /api/v1/admin/home-content/layout` | 布局草稿与当前发布布局 |
| `PUT /api/v1/admin/home-content/layout/draft` | 保存编排草稿，乐观锁 |
| `POST /api/v1/admin/home-content/layout/publish` | 校验并原子发布整版 |
| `POST /api/v1/admin/home-content/layout/rollback` | 校验并恢复上一发布布局 |
| `GET /api/v1/browse/home-editorial` | 公共读取已发布、当前仍可展示的首页内容，不返回草稿、错误详情或 prompt |

管理员预览的数据只走管理员 API，不能在公共接口加 `?draft=true` 绕过发布边界。所有失败沿用项目错误 envelope。

公共响应尽量直接返回完整展示 DTO：位置、视频事实、已解析的原句、片段时间和编辑内容，避免首页针对每张卡再单独串行请求。视频访问、媒体鉴权及片段跳转沿用现有实现，不能因首页试听绕过观看权限。

## 7. 首页接入与旧行为兼容

1. 优先读取新编排内容；有明确主推配置时，不再按视频创建时间决定主推。
2. 没有新编排时，数据退回现有 featured + learning metadata 流程；页头、学习横条和编辑式布局仍使用新设计，以保证上线初期也有完整的新首页。
3. 有新编排但部分视频失效时，过滤失效位置；次推可提升为主推；全部失效才整块走旧兜底。不能出现同一视频重复占主次位，也不能显示已下线视频。
4. 只对旧兜底继续使用 `learningStory()`；正式编辑卡直接读发布数据，不再从标题或字幕猜专题标题。
5. 点击选项只切换本地保存的反馈，可不选直接观看；选项不计为学习完成、不写用户画像，本期不持久化该选择。
6. 收词、片段试听、跟读和进度继续使用真实 API。原声播放失败给出可重试或完整视频入口，不展示假的播放成功。
7. 场景展开使用已保存参考表达，不接实时 LLM；所有加载、空态、错误态和缺失素材都能正常工作。

## 8. 来源变化、可见性和缓存

这是本功能容易遗漏的部分，必须实现而非只写注释：

- 指纹覆盖有序字幕 ID、英中内容和起止时间；生成开始、生成落库、发布时都检查。
- 字幕修改、批量编辑、增删、拆合、重排、重新分段、回滚、重新转写等会改变来源。管理员看到「来源已变更」，必须重新核对并保存或重新生成后才能再次发布。
- 旧已发布版本如果来源不再匹配，公共接口不得继续提供可能错位的引用与片段。该版本暂时失效，按第 7 节退回其它有效卡或旧展示逻辑。
- 实施时统一审查字幕写入入口，包括 worker 直接写入的流程；用集中失效入口或可靠的来源版本机制覆盖。不要只处理单句修改，漏掉重新转写。
- 视频下线、取消发布、删除、媒体失效时重新验证展示资格，复用现有访问规则和公共过滤，不照抄一个较弱的 SQL 条件。
- 新公共接口第一版可直接读数据库，不新增响应缓存，先保证发布和下线立即生效。若确需缓存，必须同时实现全部上述失效入口；不能只等 TTL。
- 旧兜底仍有 browse 缓存。源视频可见性变化后要沿用/补齐现有失效链路，不能因退回旧缓存而再次露出已下线视频。
- 首页全局内容可以共享；个人进度、复习数据不能进入公共缓存或 LLM 输入。

## 9. 实施顺序与建议文件

### 阶段 A：模型与发布语义

## 11. 最终验收：管理员真的能换一条视频

执行 agent 应演示并报告以下流程：

1. 当前首页展示视频 A。
2. 管理员选择另一条本地测试视频 B，生成草稿，修改标题和一个选项反馈，选择真实片段并预览。
3. 此时普通用户仍看到 A，且公共响应没有 B 的草稿。
4. 点击「发布并替换主推」后刷新首页，显示 B 的已发布文案、正确媒体、词语与选项反馈；不需要重新构建前端。
5. 再次修改/生成 B 的草稿，普通用户仍看到已发布的 B。
6. 恢复上一版回到 A；若 A 已下线，则拒绝恢复并明确说明。
7. AI 不可用时，可以人工编辑 B 并发布；AI 恢复后也不会自动覆盖人工内容。

交付：实际改动、迁移、自动化结果、本地联调结果、桌面/手机截图，以及「以后怎么换视频」的简短操作说明。不要在未验证时声称模型生成质量已达标；如未运行真实生成，明确该项未执行。

## 13. 「今天就能用」全文提炼：实现记录（2026-10-20）

本节记录按整段视频字幕提炼首页教学内容的实现。生成仍由管理员显式触发，结果先进入草稿；是否采用仍由管理员在预览后决定。本轮只改生成代码与后台覆盖记录，没有调用真实模型、发布内容或部署。

### 已有能力与实际缺口

- 已有后台「首页内容 → 生成草稿 → 预览 → 发布并替换主推」，无需再建生成接口或另接供应商。生成任务通过 `home_content_service.load_generation_context` 读取该视频的有序字幕，交给 `home_content_generation.generate_draft`，调用既有 `AIService` 的 `editorial` 任务路由。
- 当前本地公共接口返回 `editorial: null`，截图里的 `Kick. Flick. Skip. Punch. Yank.` 来自普通精选的 learning-metadata 样例句。它是字幕练习兜底，不能代表已经生成了全文场景。
- 提示词现在要求场景锚定表达原字幕，参考英语必须实际复用对应表达；服务端同时校验来源与复用关系，并限制不同场景使用不同表达。
- 单次预算仍为 12,000 字符。超预算时按字幕边界完整分段，每段挑选 1 条代表候选，再统一生成终稿；最多处理 32 段。超过 32 段或存在无法放入单段的超长字幕时明确失败，不抽样、不写回半成品。
- 最终提示预算不足时会报错，不再静默删掉候选段落。成功结果将字幕总句数、实际覆盖句数、分段范围和调用次数持久化，并在视频后台展示。历史任务没有覆盖数据时保持为空。
- 生成场景必须关联被选中的真实字幕与表达；字幕存在性本身不代表语义质量已经过人工审核。

### 要生成的内容

从视频的真实表达出发，产出最多 3 张用途不同的情境卡。通常取 2–3 张；不足时少展示，不为数量编造。每张复用现有结构：

| 字段 | 内容要求 |
| --- | --- |
| `situation_zh` | 简短具体的用途，如「提醒别人轻一点」，避免「日常交流」这种空标签 |
| `prompt_zh` | 一句真实情境和明确任务，让学习者知道要回应什么 |
| `reply_en` / `reply_zh` | 从视频中表达迁移出的自然参考说法及译文；明确属于教学例句 |
| `subtitle_id` | 必须指向本视频真实依据句，由服务端解析原句和时间，支持回听 |

动作教学视频可以围绕请求、提醒、描述动作选不同场景；访谈可以围绕表达观点、追问、回应选场景；知识视频可以围绕解释、比较、举例选场景。类型是选材方向，不给每种视频硬套三个固定模板。具体英语文案必须读过字幕再定，不能仅凭视频标题或首句推断。

### 实现与内容维护

1. 管理员在视频的「首页内容」区域触发生成。短字幕一次调用；长字幕逐段筛选候选并生成终稿，后台任务负责写入草稿。
2. 查看生成状态里的全文覆盖句数、分段范围、模型与 prompt 版本。覆盖限制或模型错误会显示失败原因；旧的已发布版本不受影响。
3. 人工检查场景是否自然、用途是否有差异、原字幕与英语参考句是否关联合理，再编辑草稿并预览。校验只能证明结构和引用关系，无法代替语义审稿。
4. 只有明确执行「发布并替换主推」后才影响首页。换视频时为新视频独立生成；重转写仍由来源指纹机制使旧引用失效。

实现位置：`home_content_generation.py` 的分段与候选提炼、`home_content_drafts.generation_coverage` 的覆盖记录，以及管理端视频详情的生成状态。

### 本轮边界

代码已实现并接通数据库迁移和管理状态 DTO；真实 LLM 输出质量、实际超长字幕任务耗时，以及完整后台生成/预览/发布操作尚未在本轮实测。部署前需应用新增迁移；线上生成能力在迁移生效前不应启用新字段读取。
