## 1. 产品定位与目标用户



| 项    | 结论                                          |
| ---- | ------------------------------------------- |
| 目标用户 | 四六级备考大学生为主力，考研 / 雅思人群做深                     |
| 核心场景 | 刷视频顺便学词为入口，词汇闭环做留存                          |
| 内测目标 | 验证「看视频 → 批量收词 → 快速过筛 → 掌握」闭环 + 收集真实反馈，不追求拉量 |

## 2. 上线与内测运营

### 2.1 内测渠道与链路



* 渠道：朋友圈宣传海报

* 链路：**海报二维码 → 扫码直达注册页**（无中间落地页）

* 落地页：**暂不做**（设计不佳反而拉低预期，产品介绍职责全部由海报承担）

### 2.2 海报需求



* 主视觉 = 品牌（SeeWord）+ 卖点「看视频，学单词」

* 3 秒内讲清「这是什么、对我有什么用、怎么开始」

* 福利（内测期免费开放全功能）做角标，不占主视觉

* 写明内测截止日期

* 尺寸建议：1:1 方图（朋友圈最佳）+ 3:4 竖版（备用）

* 配色：沿用现有 coral /cream/brand 品牌色系

### 2.3 免费策略



* **内测期：免费开放全功能，不引入 Pro 概念**

* 正式收费后 Pro 差异定位在「效率与深度」：不限量集合、高级复习算法、跟读额度、去广告

* 免费版必须包含完整核心闭环（看视频 + 收词 + 基本复习），否则用户学不进去

### 2.4 内测规模与周期



* 规模：50 人起步（首批种子用户，愿意给反馈）

* 周期：2–4 周（至少 2 周，观察闭环回访 / 复习行为数据）

* 同期建立反馈渠道（群 / 表单），内测用户为第一手访谈对象

## 3. 首页排行

### 3.1 榜单定义



| 榜单   | 口径       | 数据来源                               | 更新频率      |
| ---- | -------- | ---------------------------------- | --------- |
| 最新上线 | 站内上线时间倒序 | `videos.published_at`              | 实时（上线即入榜） |
| 本周热播 | 本周播放完成增量 | `BehaviorEvent`（play/complete）按周聚合 | 每日快照      |
| 本周收藏 | 本周收藏增量   | `UserFavorite.created_at` 按周聚合     | 每日快照      |

### 3.2 展示规格



* 位置：首页顶部「排行」区块（最新 / 本周热播 / 本周收藏 三 Tab）+ 「更多」进完整排行页；**不动底部导航**

* 条数：首页 5 条，完整页 20 条

* 排名徽章：1 / 2 / 3 突出，其余灰化

* 数字：播放 / 收藏数万级格式化（如 1.2 万）

* 「最新」榜显示相对时间（如 3 天前），不显示绝对日期

### 3.3 技术基础



* 复用现有 `view_count` / `favorite_count` / `published_at` / `BehaviorEvent`，**无需新埋点**

* 周榜聚合：每日快照写入缓存或快照表，接口 `/videos/rankings?scope=latest|weekly_views|weekly_favorites`

* 防刷：沿用现有完成去重逻辑，周榜按 `session_id` 去重

## 4. 词汇学习闭环（核心）

### 4.1 状态机

三态：**未学（pending）/ 学习中（learning）/ 已掌握（mastered）**



* 不做「复习中」状态；高级复习算法（间隔重复）整体放 Pro 二期

* 不做强制回看视频的闭环要求

### 4.2 批量收词（加入集合）



* 视频播放页新增「+ 加入学习」按钮

* 点击后按用户目标等级（`target_exam_level`，如 cet4）过滤该视频词表

* 一键批量生成该视频的词汇集合（不逐词添加）

* 反馈文案：「已按四级筛选，N 个单词加入词汇本」

### 4.3 词汇本视图



* 第一屏默认「视频集合」视图 +「全部单词」兜底（逐词添加的词不丢失）

* 集合卡片按「最近学习 / 未完成优先」排序（不是按加入时间）

* 集合头部放「回看原视频」入口（零成本、闭环留口）

* 集合内可筛选：全部 / 未掌握 / 学习中

### 4.4 快速过筛



* 档位：只有「会 / 不会」两档，**模糊归不会**（防止用户逃避判断、假装学会）

* 认识 → 直接标记已掌握

* 不会（含模糊）→ 自动拎出进入「待学清单」

* 中途可退出，**按词粒度保存进度**，下次续筛

* 退出时轻反馈：「已保存，下次从第 N 个继续」

### 4.5 闭环终点



* 学完待学清单 → 全部标记已掌握 → 集合进度 100% → 闭环完成

* 写入 `LearningEvent`（learned\_words）联动档案 / 里程碑

* 学完集合后靠「新视频上新 + 成就感反馈」驱动回访（内容更新需持续）

### 4.6 数据模型原则



* 新增 `vocab_sets`（用户 × 视频 × 等级 唯一）与 `vocab_set_words`（集合内词 + 状态）

* **集合里的词 = 词汇本里的词，只是「按视频聚合」的视图，不建两套数据**

* 不复用已下线的 LearningPlan / LearningPlanItem 表（f855613）

## 5. 存储架构方向

### 5.1 内容三态（`videos.storage_mode`）



| 模式            | 含义                 | 功能                          | 存储     |
| ------------- | ------------------ | --------------------------- | ------ |
| `local` 本地精品  | 下载转码到本地            | 全功能（精翻字幕 + 词标注 + 点词 + 批量收词） | 占用本地空间 |
| `proxy` 代理播放  | 不下载媒体，播放器走 YouTube | 仅观看 + 收藏 + 排行可见，**不可收词**    | 零占用    |
| `offline` 已下线 | 从首页 / 推荐 / 排行隐藏    | 保留学习记录不断链                   | 释放媒体文件 |

### 5.2 代理视频规则



* **不进主 feed**，独立「源视频」区，明确标注「需网络环境」

* 定位为浏览 / 引流层，完整学习体验只在本地精品上

* 第一期不做代理视频的字幕 / 点词

### 5.3 下线机制（半自动）



* 触发：数据阈值自动「建议下线」（上线 N 天 + 播放 / 收藏 / 完成率低）+ 管理员一键确认；人工判断为辅

* 动作：隐藏 → 确认无活跃学习记录 → 删除本地媒体文件释放空间（video 行保留 dormant）

* 被下架视频的收藏用户不主动通知，但收藏夹保留入口并标注「已下架」

### 5.4 存储解法优先级



1. 下架机制（立刻释放空间）

2. 入库精筛（只处理精品）

3. 代理播放（远期 / 占位）
