为什么推荐 R5

  • ② 的答案：字幕不再是「一个盒子」。R0 里画框与当前句之间有 12px 白缝、再一条上下都封边的白带 —— 白底上凭空多出两条线；R5 把字幕带与画框齐平并去掉外框，画框下沿就是唯一的边，字幕回到「画面这一块」。
  • ② 的答案：模式行有了归属。它管的是「这一面的文字怎么显示」。放进文稿卡的卡头（带两条发丝线的工具栏）之后，它是文稿这个容器的工具条，而不是夹在两块内容中间的一行 chip；用户不再看到「字幕 → 一行 chip → 字幕稿」这种三段式。
  • 顺手修两个真问题：① 折叠键在移动端没有对象（panelCollapsed 折出的竖轨并不真的让出一列，而且 ≤1023px 下没有任何 spec 依赖它）；② 现在的 chip 行只有 32px 高、不到 44px 触控基线，换成分段控件正好补上。
  • 代价是 0 条断言。卡与画框同 x 同宽、卡顶 = 画框下沿（0 ≤ 16）、露出画面 233px（≥120）、计数仍在卡内且唯一、模式行仍是 role=tablist —— 六条硬约束一条都不碰；而且比现状少 12px，首屏文稿从 4 条起。
R5 需要拍板的三件事：
① 0 断层：字幕紧贴画框下沿（现在是 12px）。规格允许 0…16px，所以零风险；但视觉上比现在紧 —— 若觉得挤，改成 6–8px 也一样过（区间内自由）。
② 重复：当前句与文稿第一行是同一句话（现状也重复，只是被 chip 行隔开）。三个处理：(a) 接受；(b) 文稿里的当前项降级为「淡底 + 左侧竖线 + ink 文字」，橙色只留给当前句；(c) 取消字幕带，直接以文稿当前项为唯一渲染（要重写 INV-021，不建议）。
③ ⋯ 面板里那份「语言」留不留：我倾向留（设置面板里重复一个设置是正常的，面里这份是快捷方式）。
如果想让字幕更像播放器的一部分 → 选 R3（深底白字，零 spec 改动，代价在配色）。
如果更想要「一张面」的整体感 → R1，但要接受：卡顶离画框 31px（破 mobile-inline-subtitle:114）、卡与画框不同宽（破 mobile-current-sentence-card:152-156）、INV-021「直接位于画框之下」的措辞要改，并且按仓库规矩走一次 /decision-support 落 DEC。
R6 只差一条断言（卡内下 1/5 不放控件）—— 要选它就同步把 mobile-current-sentence-card:232 的取样点改成「模式行之上」，说清楚「卡内允许有一条工具行」。
