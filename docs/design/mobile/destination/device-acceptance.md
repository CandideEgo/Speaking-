## 1. 前置：把 iPhone 接到本地 dev

### P1 · 电脑侧把栈起起来

```powershell
docker compose -f docker-compose.dev.yml up -d      # db + redis
cd backend ; .\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
cd frontend ; npm run dev                            # :3000
```

本轮执行时这台机器上 `:3000` 与 `:8000` **都已在监听**（Next dev 监听 `::`，双栈，所以局域网 IPv4 能连）。

### P2 · 拿到局域网 IP

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } |
  Select-Object IPAddress, InterfaceAlias
```

**本轮实测（这台机器）**：`192.168.1.109`（以太网）、`192.168.1.192`（WLAN）。手机连的是哪个网就用哪个 ——
手机和电脑必须在同一个子网，`172.x` 那两个是 WSL/Hyper-V 虚拟网卡，不要用。

### P3 · `allowedDevOrigins` 放行（**已核实的真实写法**）

配置文件是 `frontend/next.config.js`（**不是** `next.config.ts`），第 21 行：

```js
allowedDevOrigins: (process.env.DEV_ALLOWED_ORIGINS || "192.168.*.*").split(","),
```

- **默认网段就是 `192.168.*.*`**，本机的 `192.168.1.109` / `192.168.1.192` 已被覆盖 —— **不改配置也能连**。
- 别的网段（如 `10.x`、`172.16.x`）用环境变量覆盖，**逗号分隔、不要加空格**（代码只 `split(",")`，不做 trim）：
  ```powershell
  $env:DEV_ALLOWED_ORIGINS="192.168.*.*,10.0.*.*" ; npm run dev
  ```
  环境变量是**启动时**读的，改完必须重启 dev。
- 匹配语义（Next 自带文档 `frontend/node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/allowedDevOrigins.md`）：
  只拿请求 `Origin` 头的 **hostname** 来比（scheme / 端口 / 路径一律忽略，所以条目里也不要写端口）；
  `*` 代替**一个** label，`**` 代替一个或多个 label 且**只能写在开头**。
  所以 `192.168.*.*` ✓、隧道用 `*.trycloudflare.com` ✓（写成 `**.trycloudflare.com` 也行，但 `*` 已够）。

**怎么确认放行生效**（这两条命令本轮实测过，读数如下）：

```powershell
# 取一个 dev 专有资源的真实 URL（哈希会变，所以现取现用）
$html  = curl.exe -s http://127.0.0.1:3000/login
$asset = [regex]::Match($html, '/_next/static/[^"'']+\.js').Value

# ① 放行网段：应 200
curl.exe -s -o NUL -w "%{http_code}`n" -H "Origin: http://192.168.1.109:3000" "http://127.0.0.1:3000$asset"
# ② 未放行网段（拿 10.9.9.9 冒充）：应 403
curl.exe -s -o NUL -w "%{http_code}`n" -H "Origin: http://10.9.9.9:3000" "http://127.0.0.1:3000$asset"
```

- 本轮读数：**① 200 / ② 403**（无 Origin 头也是 200）→ 默认网段确实放行了，机制也确实在拦。
- **没放行的症状**不是白屏报错，而是**页面停在骨架屏、一个 API 都不发**（HMR WebSocket 被挡，见 `next.config.js:17-20` 的注释）。
  在手机上看到骨架屏不动，先回来查这一条。

### P4 · Windows 防火墙

手机是**从外部**连进来的，`node.exe` 必须被允许入站。本轮实测这台机器已有 `node.exe` 的 Inbound/Allow 规则（Public 配置文件）。

### P6 · 登录：**dev-fake 验证码这条路走得通**，不用去日志里捞码

**已核实的事实链**（本轮实测，不是推断）：

- `backend/.env` 只配了 `SMS_LOGIN_ENABLED` / `ALIYUN_SMS_SIGN_NAME` / `ALIYUN_SMS_TEMPLATE_CODE`，
  **没有** `ALIYUN_SMS_ACCESS_KEY` / `SECRET_KEY` → `_real_send_enabled()` 为假、`_dev_fake_enabled()` 为真
  （`backend/app/services/sms_service.py:99-117`；`env` 默认 `development`，见 `core/config.py:26`）。
- dev-fake 下验证码是**固定字面量 `1234`**（`sms_service.py:66`），`verify_code` 在 dev-fake 下**只认它**（`sms_service.py:196-204`）。
  日志里那行 `[sms-fake] code=1234 for 138****（purpose=register）`（`sms_service.py:139`）只是佐证，
  **你不需要去电脑上读日志**。
- 端到端实测（走 `:3000` 的 dev 代理，和手机同一条路）：`POST /api/v1/auth/sms/send-code` → **200**，
  再 `POST /api/v1/auth/sms/register {code:"1234"}` → **201 + token**，`onboarding` → 200。

**路 A（推荐）：在手机上直接注册，注册即登录**

1. 手机开 `http://<IP>:3000/register`
2. 手机号随便填一个**没在本库注册过**的合法号（`1[3-9]` 开头 11 位；图省事可以用你自己的号段随便编一个）
3. 点「获取验证码」→ 验证码填 **1234**
4. 密码填 `TestPass123`（策略：≥8 位、含大小写字母和数字）
5. 勾选条款 → 提交。新用户会先到 `/onboarding`，走完或跳过即进首页

**路 B（手机号已被注册过时）**：电脑上先注册同一个号（浏览器开 `http://localhost:3000/register`，同样填 `1234`），
之后手机走 `/login` 用**手机号 + 密码**登录（`/login` 页只有密码登录，没有验证码输入框 —— 全仓只有
`/register` 与 `/forgot-password` 有验证码输入，见 `frontend/src/app/register/page.tsx:150`）。

**限流（本轮亲测会踩）**：全部按 IP 计。手机流量经 dev 代理转发后，后端看到的也是 `127.0.0.1`，
**和电脑共用一个桶**：

| 接口 | 限额 | 备注 |
|---|---|---|
| `/auth/sms/send-code` | 5/分钟 | `auth.py:52` |
| `/auth/sms/register` | **3/分钟** | `auth.py:107`；本轮连跑两次就吃到 `429 RATE_LIMITED` |
| `/auth/login`（密码） | 5/分钟 | `auth.py:164` |

被限流了就等 60 秒，或按 `.agent/state.md` 的清法清 Redis：`LIMITS:LIMITER/127.0.0.1//api/v1/auth/sms/{register,send-code}*`。

## 2. 关键风险：局域网 http 下「跟读录音」**验不了** —— 两条路选一条

**事实链（已核实）**：

1. 真机走局域网 http 时**不是安全上下文** —— 上一轮探针读数原文就写着 `安全上下文（https） = 否（http）`
   （`baseline/probe-2026-09-30.txt:25`）。
2. `getUserMedia()` **只在安全上下文可用**；非安全上下文下 `navigator.mediaDevices` **根本不存在**，
   调用会抛 `TypeError`（MDN：[getUserMedia — Secure context](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)）。
3. 本仓库的跟读录音正是走 `navigator.mediaDevices.getUserMedia` → `MediaRecorder`（e2e 里就是靠替换这两个对象造假的，
   见 `frontend/e2e/mobile-wordcard-drawer.spec.ts:36-65`）。

**所以：在 `http://192.168.x.x:3000` 上，V7 录音这一项不可能做出来** —— 探针 D4 会先把这两行打给你看：
`isSecureContext = 否` / `navigator.mediaDevices = 不存在`。**别等跑到 V7 才发现。**

### 方案 A（要验录音就上 HTTPS，确切做法）

用 Cloudflare 的 **Quick Tunnel**（不需要账号、不需要域名）：

```powershell
winget install --id Cloudflare.cloudflared        # 装一次
cloudflared tunnel --url http://localhost:3000    # 输出一个 https://<随机词>.trycloudflare.com
```

**必须同步改的配置**（不改的话手机打开 tunnel 会卡在骨架屏）：把 tunnel 域名加进 `allowedDevOrigins`，
然后**重启 dev**：

```powershell
$env:DEV_ALLOWED_ORIGINS="192.168.*.*,*.trycloudflare.com" ; npm run dev
```

- 手机开 `https://<随机词>.trycloudflare.com/register` 走 P6 登录，再开
  `https://<随机词>.trycloudflare.com/probe-device-check.html?fit=cover`。
- 探针报告里应看到 `安全上下文 = 是`、`navigator.mediaDevices = 存在`、`getUserMedia = 成功` → 此时 V7 才能做。
- API 不用另外配：dev 的 `/api` 与 `/media` 是 Next 自己 rewrite 到 `localhost:8000` 的（`next.config.js:30-39`），
  浏览器只访问 tunnel 那一个源。
- 代价与注意（[Cloudflare Quick Tunnels 文档](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)）：
  **URL 即凭证、公网可达**（验收完 Ctrl+C 关掉）、域名每次重启都变（变了要重设 `DEV_ALLOWED_ORIGINS` 并重启）、
  不支持 SSE、约 200 并发上限。

### 方案 B（不上 HTTPS）：V7 明确标注**本次局域网不可验**，走替代路径

替代路径按价值排序：

1. **本地 e2e 已经覆盖到「回放态」**：`mobile-wordcard-drawer.spec.ts` 用假麦克风真跑完了
   `录音 → 停止 → 重录/满意/下一句`（含计时格式与 44px 动作行）。录音的**状态机**不是无人区。
2. **真机上只验不需要麦克风的那一半**（V6）：抽屉几何、计时走字、44px、下拉关闭、播放器逐像素不动。
3. **留给 HTTPS 那一轮**：权限弹窗文案与时机、录制中的实时波形是不是按容器实宽（291px）、
   停止后 blob 上传与「已保存」、原声/自己两条波形的对比。

> 清单里 **V7 直接标成「不可验（需 HTTPS）」**，不要在这一轮把它算成「未通过」。

## 3. 逐项清单（V1–V18）

每条先给定位，再给判定。**记录格式**里 `____` 就是回传时要填的读数位。
「探针 C 段」= 在探针页 C 区里操作真实播放页，然后点一次「量一次」。

### V1 首屏就是画面（INV-024）`[探针+人眼]`

- **怎么做**：手机竖屏，打开 `/watch/<id>`，**不要滚动**。看探针 C 段（尺寸选 375×812 或 414×896）。
- **看什么**：画框左边界、宽度、顶边、标题、动作行。
- **通过标准**：`画框 x ≈ 0`、`画框宽 = 视口宽`（375 档 375±1 / 414 档 414±1）、`画框顶边 ≈ 壳顶（main#main-scroll top）`（|Δ| ≤ 1）；
  标题 overlay 落在画框**内部**；`桌面页头 h1 可见 = 否`；动作行在画框下方且高 ≥44；人眼确认：页头那行「返回/标题/点赞/元信息」**不在画面之上**。
- **记录**：`V1 = 画框 0/375/210.9 顶=壳顶Δ0 标题在内 h1=否 动作44 ____`

### V2 入画字幕贴画框最下沿 + 常驻 3px 细进度（INV-021）`[探针]`

- **怎么做**：仍在首屏，播放中。C 段量一次。
- **看什么**：`入画字幕`矩形、`细进度`高度、露出画面高度。
- **通过标准**：`入画字幕底边 + 3 − 画框下沿 = 0`（|Δ| ≤ 2）；`细进度高 = 3`；`露出画面 ≥ 120px`（375 档参考读数 ~129.8px@414 / 复刻 130.5@375）；
  字幕块与画框同宽同 x；字幕块有实际高度（>20px）。
- **记录**：`V2 = 字幕底+3−画框底 __ 细进度 __ 露出画面 __`

### V3 点画面浮起控制条、3s 自收、字幕一个字不动（INV-021 / #28）`[探针+人眼]`

- **怎么做**：**点一下画面中部**（不要点词，避开字幕条那两行）→ 等 4 秒；再点一次。
- **看什么**：`controls-bar` 的 y 值相对画框下沿；字幕块 y 是否变化。
- **通过标准**：点后 `控制条 y < 画框下沿 − 40`（浮起）；浮起时**入画字幕 y 变化 < 1px**；**3 秒后**控制条整体沉到 `y ≥ 画框下沿 − 2`（自收）。
- **记录**：`V3 = 浮起 y __ 字幕Δ __ 3s 后 y __`

### V4 点词与点画面错开 + 行内热区可达（INV-021/022 / #27）`[探针+人眼]`

- **怎么做**：在**画面内那句**上连续点 **5 个不同的单词**（每次点完关掉词卡）。
- **看什么**：是否弹出词卡、词卡对的是不是刚点的那个词、控制条有没有被顶起来。
- **通过标准**：**5/5** 都弹出词卡、`[data-testid="word-tooltip"]` 的 aria-label 与刚点的词一致；
  点词后控制条**没有被顶起**（`控制条 y ≥ 画框下沿 − 2`）。行内热区读数（探针给）：16px 字号下**排版高 21px、含 `::after` 外扩的有效命中高 28px** ——
  **44px 在行内做不到，这是 #27 已记账的代价**，不作为不通过项，但错位次数要记下来。
- **记录**：`V4 = 命中 5/5（或 __/5） 错位 __ 次 控制条未顶起 __ 热区读数 __`

### V5 词卡卡口与高度（INV-022 / #27）`[探针]`

- **怎么做**：点画面内一个词 → C 段量一次；再点词卡里的「加入词库」。
- **看什么**：词卡顶边、卡高、卡底与底栏顶的关系。
- **通过标准**：`词卡顶边 − 画框下沿 = 0`（|Δ| ≤ 2，**不许为负** —— 负就是压住了刚点的那句）；
  `卡底 ≤ 底栏顶`；且 `卡底 ≤ 底栏顶 − 80`（高度随内容，不是拉满屏）；点「加入词库」后词卡**不自动关**。
- **记录**：`V5 = 卡顶−画框底 __ 卡高 __ 卡底−底栏顶 __ 加词后仍开 __`

### V6 跟读抽屉：几何、播放器不动、计时、44px、下拉关闭（INV-022 / #26 / #29）`[探针+人眼]`

- **怎么做**：点动作行的「录音」→ 抽屉升起 → C 段量一次 → **按住抽屉顶部把手下拉 >64px**。
- **看什么**：抽屉顶边/底边/高度、画框在展开前后的 y 与 height、计时文本、动作按钮高度。
- **通过标准**：`抽屉顶边 ≥ 画框下沿`（不许压画面）；`抽屉底边 − 底栏顶 = 0`（|Δ| ≤ 2）；
  `抽屉高 ≤ 400`；**展开前后画框 y 与 height 逐像素相等**（|Δ| ≤ 1）；计时显示 `m:ss` 且**秒在走**（不是恒 0:00）；
  动作行每个按钮高 ≥44；下拉 >64px 抽屉关闭。
- **记录**：`V6 = 抽屉 y __ h __ 画框Δy __ Δh __ 计时 __ 44px __ 下拉关 __`

### V7 跟读录音本身（**局域网 http 不可验**）`[探针]`

- **怎么做**：先点探针 D4「测麦克风」，看三行读数。
- **通过标准**：
  - 若 `navigator.mediaDevices = 不存在` → **本项标记「不可验（需 HTTPS，见第 2 节方案 A）」**，不是失败；
  - 若在 HTTPS 下（`安全上下文 = 是`、`getUserMedia = 成功`）：点「录音」→ 允许麦克风 → 抽屉进入录音态、计时走字、
    波形按容器实宽铺开（375 档约 291px）→ 点「停止录音」→ 出现「重录 / 满意 / 下一句」。
- **记录**：`V7 = 安全上下文 __ mediaDevices __ getUserMedia __ 结论 __`

### V8 ★ 滚动后的画面形态（INV-023 / #30）`[探针+人眼]`

现在 0×0 一律记「未渲染」；`dblclick` 监听声明了却没挂上，现在真的挂了（`未缩放 · dblclick 到达 = 是` 才是可信读数）。

**自查用的临时文件已全部删除**（`frontend/public/probe-device-check.html`、`frontend/public/_probe-stub2.html`、

### 5.3 这个量具页量不到什么（别指望它）

- **地址栏收放对 app 的影响**：iframe 里没有地址栏，`dvh` 永远等于 iframe 高度。地址栏只能看 A 段（同理那条 `100dvh − 可视高`）。
- **双击缩放 / 长按菜单的真读数**：桌面 Chromium 没有 iOS 的双击缩放，自查只能验证「判定逻辑给出确定结论」；
  真读数必须在这台 iPhone 上出。
- **安全区**：只能用 `env()` 折算出真实像素（`padding` 探针）；Chromium 无法伪造 insets，所以 e2e 永远给不了这条。
- **原生全屏**：`webkitEnterFullscreen` 只在真机存在，探针只能记录「全屏后剩下什么」，判不了。
- **B 段的绝对像素**：与 app 差几 px（字幕行数随句子长度变），所以 B 段读的是**关系**（差值为 0 / ≥0 / ≤400），
  绝对值以 C 段的 app 读数为准。

## 附：本轮核实过的、与文档写法不同的地方

1. **`allowedDevOrigins` 在 `next.config.js` 而不是 `next.config.ts`**，写法是
   `(process.env.DEV_ALLOWED_ORIGINS || "192.168.*.*").split(",")`，**默认网段确实是 `192.168.*.*`**；
   匹配只认 Origin 的 hostname，`*` = 一个 label，逗号分隔**不 trim**。
2. **`dev-fake` 验证码是固定 `1234`，不需要读日志**：`backend/.env` 没有阿里云 AK/SK，`_dev_fake_enabled()` 为真；
   手机走 `/register` 填 `1234` 即可（本轮端到端实测 201）。
3. **探针页在登录墙后面**（`proxy.ts` 的 matcher 不放过 `public/` 下的任意 html），所以必须**先登录再开探针**。
4. **局域网 http 是 `navigator.mediaDevices` 直接不存在**（不是「调用被拒」），录音那一项只能在 HTTPS 下验。
5. `frontend/e2e/*.spec.ts` 里没有 `/watch` 的壳层路由覆盖，也没有任何一条覆盖 `WordCardSheet` 的 clamp 落档分支
   —— §7 的第 1、6 条就是补这两处。
