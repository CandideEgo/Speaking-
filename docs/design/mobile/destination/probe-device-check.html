seeword 真机验收探针

自包含单文件（无外链、无框架）。只为 wayfinder #20 destination 的真机验收取读数，不随生产构建发布 —— 它住在 docs/design/mobile/destination/，要跑时拷进 frontend/public/。 数字全部来自浏览器 API 与 getBoundingClientRect()，不是目测。

怎么用

  1. 电脑：copy docs\design\mobile\destination\probe-device-check.html frontend\public\（dev 站要跑在 :3000）
  2. 手机 Safari 打开 http://<局域网IP>:3000/probe-device-check.html?fit=cover。先登录（否则登录墙会把你弹到 /login —— 探针页也在墙后面）
  3. 点「开始（记本机信息）」→ 得到 [dev] 段
  4. 上滑让地址栏收起 → 「记 A」；下拉露出地址栏 → 「记 B」
  5. 点「量复刻版式」→ 得到 [复刻] 段（本页把 app 的移动端几何按同一套数值搭出来量）
  6. 点「测伪全屏几何」→ 屏幕闪一层橙色覆盖层，得到 [伪全屏 #25 P6] 段
  7. （可选，最有用）C 段载入真实播放页，量真实 DOM：首屏 → 滚走 → 点词 → 开抽屉，各点一次「量一次」
  8. D 段按提示做手势（双击 / 长按 / 单击 / 纵向拖），E 段是只有人眼能判的项
  9. 滚到底 → 「选中报告」→ 长按文本框 → 全选 → 拷贝 → 贴回给 Lead（原文逐字存盘，见 device-acceptance.md）

读数会自动存在本机（localStorage）：切到别的 App、Safari 重载、甚至误触下拉刷新，回来都还在； 想从头再来就点「清空全部读数，重来」。

http 下没有剪贴板 API：局域网 http 不是安全上下文，所以「尝试复制」会退化成手动全选拷贝 —— 这是预期行为，不是坏掉。 另外 http 下 navigator.mediaDevices 根本不存在，跟读录音那一项要 HTTPS 才能验（见 device-acceptance.md 的「关键风险」一节）。 

（#25 P6：点上面那个按钮，屏幕会闪出一层 position:fixed; inset:0 的橙色覆盖层 —— 它要回答的是「自绘伪全屏」到底能不能盖住可视区，还是像 fixed 一样伸出 40px。）

D · 手势（本页复刻元素上做，自动判）

D1 双击是否触发页面缩放

点下面按钮 → 在亮起的框里双击（1 秒内两次）。touch-action: manipulation 是「不要双击缩放」的标准写法（app 里单词热区也是它）。 判定：dblclick 事件到达 = 浏览器没缩放；visualViewport.scale 变大 = 缩放了。

D2 长按是否出菜单 / 选中

点按钮 → 在两个框里各长按单词 1 秒。左框是 app 的画法（父层 select-none，无 callout 抑制）， 右框加了 -webkit-touch-callout:none。判定记录 contextmenu 事件与是否选中了文本。

app 画法（select-none）——长按 welcome
callout 抑制（touch-callout:none）——长按 welcome

D3 单词单击延迟（#29 的输入）

点「测单击」→ 点一下单词。记录 touchstart → click 的毫秒数：manipulation 下应 < 50ms，没写的话 iOS 经典 300ms 延迟。
