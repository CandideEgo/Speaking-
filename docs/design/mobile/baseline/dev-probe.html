seeword 真机量具

一次性页面，只为 wayfinder #22 取真机读数；票关了就删。数字全部来自浏览器 API，不是目测。

怎么用

1. 上滑页面让 地址栏收起，点「记 A」。
2. 下拉让 地址栏出现（或用手指把页面往上拖一下露出地址栏），点「记 B」。
3. 看下面的「A → B 差值」：100vh 减可视高度的差值就是底栏被切掉的像素。
4. 截图时留意两条色带：页面顶边那条 品红、底栏下沿那条 青色。 青色条还在 = 45px 底栏完整贴在可视区底部；青色条看不见 = 底栏下沿被切掉了。
5. 点「选中报告」→ 长按文本框 → 全选 → 拷贝，贴回来给我；或者直接截图这一屏。
但安全区那一栏（0 还是 34）只有贴文本才靠得住：拍屏后小字数字读不出来，四张 cover 截图就是这么废掉的。

两件事，各来一遍

① 视口（第 1/2 条）：这一屏默认 fit=auto（= 应用现在的写法不敷 cover 时的样子）。点下面的「记 A」「记 B」各一次 → 复制报告。
② 安全区（cover）：点本文的「切到 fit=cover」→ 页面重载 → 再点「记 A」「记 B」各一次 → 复制报告（这次务必贴文本）。

安全区（env(safe-area-inset-*)）

当前 模式。读数为 0 是可能正确的，不一定是坏事：社区共识是 viewport-fit=cover 生效时 insets 才有值（否则恒为 0），而 iOS 26 起 Safari 浏览器模式下 cover 可能根本铺不进上下工具条区 —— 真机上这两种情况都见过。 切到 fit=cover 看「如果加了 viewport-fit=cover 会拿到多少」—— 这个数字决定刘海 / Home indicator 要预留多少，直接给 #25 / #30 用。 读数请贴文本，别拍屏：这一栏是小字号右对齐数字，照片上分不出 0 和 34。
