## 任务 3：服务器视频封面加载异常（P0，先修封面，HK 迁移暂缓）

### 已核实事实

- 仓库内 `nginx.ssl.conf:115-135` 把 `/media/` 代理到 **backend 容器**，仓库中**不存在任何 HK VPS 代理配置**。`.agent/context.md` 所述「媒体存 HK VPS、源站 nginx 代理」与仓库实现不符（REVIEW-2026-08-14 §214 已指出该运维可复现性缺口）→ 实际代理配置很可能在服务器上手工维护、游离于仓库之外。
- `Video.thumbnail_url`（backend/app/models/video.py:58）可为本地路径 `/media/{id}_thumb.jpg` 或外部 URL（ytimg/hdslb 等）；外部 URL 由前端 `mediaUrl`（frontend/src/lib/api.ts:51-85）转发到后端 `/media/proxy?url=` 抓取。
- 历史记录：HK VPS 上 YouTube 不通、`HTTP_PROXY` 曾指向不存在的代理（docs/reports/video-pipeline-deep-dive-2026-08.md:111）。

### 根因假设（按可能性排序）

1. 封面为外部 URL → `/media/proxy` 抓取失败：服务器直连不到 ytimg，而代理依赖即将到期的 HK 服务器（或已失效的代理地址）。
2. 服务器上实际的 `/media/` 代理指向 HK 服务器（仓库外配置），HK 异常导致 404/超时。
3. 封面在本地卷但路径/卷挂载不对。

### 步骤

1. **只读诊断**（SSH）：统计 DB 中 `thumbnail_url` 形态分布（本地 vs 外部）；`nginx -T` 查仓库外配置；curl 实测封面 URL 状态码；查 `/media/proxy` 错误日志。
2. **按结果修复（目标：封面不再依赖 HK）**：
   - 外部 URL 代理失效 → 写一次性回填脚本：下载封面到本地 `{id}_thumb.jpg` 并更新 DB 为本地路径，彻底摆脱外部/代理依赖。
   - 媒体实际在 HK → 把封面（必要时全部媒体）拷到剩余服务器，并把配置统一收编进仓库内 `nginx.ssl.conf`。
3. **知识维护**（仓库规范强制）：修复后更正 `.agent/context.md` 媒体分发段落，并在 `docs/operations/` 补齐真实拓扑。

### 缺口与风险

- HK 服务器同时是 `seeword.top` 的 SSL 反代入口，GPU worker 回调也经它中转（docs/operations/GPU-WORKER-SETUP.md）。**本次按你决定只修封面、不动入口**；但需明确：一旦 HK 到期，影响是全站入口＋转写管线，届时需整体迁移。建议在 `docs/operations/` 留一条「HK 到期迁移预案」占位，避免到时仓促。
- 封面回填脚本下载外部图需走可用网络；若服务器直连 ytimg 不通，回填需在有外网的机器上执行后 rsync 回服务器。

## 任务 1：前端体验修复与设计减法（P1）

> 本任务拆两条线：**1A 试卷模块功能修复（bug）** 与 **1B 个人中心设计减法（体验）**，性质不同、可并行。

### 1A 试卷模块「选项无法选择」（两端均复现）

**已核实事实**
- ExamRunner（components/exam/ExamRunner.tsx:208-235）选项是带 onClick 的 `<button>`；PracticePanels（components/practice/PracticePanels.tsx:72-106）用 `<label>` + sr-only radio，判分后 `locked` 锁定。代码层面无明显禁用/遮挡。
- 嫌疑点：MainLayoutInner.tsx:26 对已认证用户设 `html.style.overflow="hidden"`，配合嵌套滚动容器（L75/L77）可能产生滚动/点击异常；移动端固定底部栏（`fixed bottom-0 z-40`，ExamRunner L247）遮挡末尾选项。
- **关键**：因两端均复现，纯移动端遮挡假设不成立 → 更可能是滚动容器 / z-index / 事件层的通用问题。

**步骤**
1. **先复现**：桌面＋移动各走一遍出卷→选择→提交流程，录屏/截图定位「无法选择」的确切原因。
2. 按根因修复（滚动容器层级 / 点击区域 / 事件绑定）。
3. 补 Playwright e2e：答题→判分→错题本流程（state.md 已记录考试 e2e 缺失，防回归）。

### 1B 个人中心与设置页「设计减法」

**问题定性**（据你的反馈）：风格不统一、功能按键太多、选项多且杂、做减法未真正从用户体验出发。**这是设计问题，不是代码 bug**——代码排查确认 profile/SettingsTab 已规范使用语义 token 与 ui 组件。

**步骤**
1. **信息架构梳理**：把个人中心/设置页现有全部功能按键与选项列成清单，按使用频率与核心价值分层（核心 / 次要 / 可收纳 / 可砍）。
2. **减法方案**：核心动作保留外露，次要收进二级/折叠，低频或冗余直接下线；每个被砍/收纳项写明理由（从用户任务出发，而非为简而简）。
3. **风格统一**：以 watch 页为锚点，统一按钮/卡片/间距/色彩 token；ExamRunner 目前**未复用任何 ui/ 组件**（全手写内联样式），一并改造接入设计系统。
4. 改造后桌面＋移动双端走查确认。

### 缺口

- 2026-08-14 已做过一次全站审查（24 用户页＋9 管理页对原型）。本次 1A 是功能修复、1B 是设计减法，均不重复全量审查。
- 1B 的「砍哪些按键」需要你拍板——减法涉及功能取舍，方案出来后会列清单请你确认再动。

## 任务 2：视频频道功能（P2，先写 ADR）

### 已核实事实

- Video 模型已有 `yt_video_id / channel_* / upload_date / ext_*` 外部元数据字段（ADR-0011 阶段 1），频道信息有数据基础。
- UGC 已砍（ADR-0012）→ 频道只针对官方视频，本质是**官方策展维度**。
- 推荐已有 `/recommendations/category/{tag}` 分类维度（feedStore 承接）。

### 方向草案（需先走 decision-support 写 ADR，入 docs/adr/）

1. 数据模型：Channel 实体（管理员维护）＋ Video 关联＋DB 迁移；或轻量方案：按 `channel_name` 聚合不建表。
2. 后端 API：频道列表 / 频道详情 / 频道内视频分页。
3. 前端：频道页、视频卡频道入口、浏览页频道维度。
4. 管理后台：频道创建 / 编辑 / 排序 / 封面。
5. 订阅/关注：**建议一期不做**，仅展示＋分组。

### 缺口

- 属新功能/架构变更，按仓库规范必须先写 ADR。
- 频道与现有 category/tag 推荐维度的关系需在 ADR 里定死，避免两套并行浏览体系。
- YouTube 频道元数据是抓取来的（channel_* 字段），与「站内频道」如何映射要在 ADR 里明确。
