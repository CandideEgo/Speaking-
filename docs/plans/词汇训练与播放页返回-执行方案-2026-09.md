**测试**：新增 `frontend/src/lib/watchEntry.test.ts`（映射表与 URL 构造；符合现有 vitest 范围 `src/**/*.test.ts(x)`，`frontend/vitest.config.ts:14`）。组件无单测先例，不要为此新立约定，交互用 e2e 冒烟。

### S6｜复习间隔新算法 + 同日优先级（`vocab-learning`）

**这是一次算法替换**（设计文档 §5.4）：现行 `backend/app/services/sr_service.py:47-64` 的 `1 / 6 / interval × ease_factor` 改为按错误次数分档：

| 情况 | 下次复习 |
|---|---|
| 本轮内答错过 | 次日（1 天） |
| 本轮内一次没错 | 3 天后 |
| 复习时答错 | 回到次日，`wrong_count += 1` |
| 全对且 `wrong_count = 0` | 3 → 7 → 16 → 35 天 |
| 全对但 `wrong_count ≥ 1` | 2 → 5 → 12 → 25 天 |
| `wrong_count ≥ 3` | 间隔上限 7 天 |

保留 SM-2 的所有列（`ease_factor` 不再参与计算，留作兼容）。对齐 `backend/app/services/vocabulary_service.py:129-140` 的复习队列排序为：昨天错过的优先 → `wrong_count` 降序 → 到期时间升序。`api/v1/vocabulary.py:260-323` 的 review 端点补写 `wrong_count` / `last_wrong_at`。

**验收**：表驱动测试覆盖上表六个情形 + 同日排序（构造「昨天错 3 次 / 昨天错 1 次 / 昨天没错」三个词，断言出队顺序）。**必须补 DEC 条目**。
