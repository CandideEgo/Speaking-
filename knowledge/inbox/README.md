# inbox — 原话的存放处

> 一段口播原话进来，出去的是「每一句都有去向」的清单。这里存的是**你说的**，不是**整理过的**。

## 为什么单独一层

原话是素材，不是文档，也不是知识。它有三个别的目录都没有的性质：**不可编辑**（改一个标点
就失去证据价值）、**不参与知识层的链接与体积规则**（它天生冗长）、**唯一的用途是被引用**
（方案、决策、工单都要能指回它）。所以它有独立的目录、独立的文件形状和独立的检查。

## 一个 capture 长什么样

```
knowledge/inbox/
  2026-09-29-01-口播需求管线/
    raw.md       ← 你的原话，逐字；封存之后正文一个字都不许动
    triage.md    ← 一段一行：摘要 / 处置 / 去向
```

目录名 = `<id>-<slug>`，其中 id 是 `YYYY-MM-DD-NN`（当天第几次口播）。引用某一段时写
`2026-09-29-01#S07`。这个 id 与段号必须真实存在 —— 全仓任何地方这么写，`captures` 检查都会
去解析它，指错了会被拦下。

## raw.md：内容冻结，格式自由

正文是**你的原话逐字**，包括口误、重复、前后矛盾、错别字。矛盾本身是信号（它正是「要决策」
的候选），所以不许顺手理顺。

段落之间插剪切标记，把原话切成段：

```markdown
<!--#S01-->第一段原话……

<!--#S02-->第二段原话……
```

标记就是剪辑点：**可以移动、可以重切**，标记之间的字一个都不能改。正文必须以 `<!--#S01-->`
开头，否则标记前面那段文字归属不明，检查会问它属于哪一段。

frontmatter 是这张 capture 的行政记录，可以改：

```yaml
title: 口播原话 — <一句话说明这次口播在说什么>
capture: 2026-09-29-01
source: voice        # voice | text
status: open         # open | closed
created: 2026-09-29
updated: 2026-09-29
```

**可改与不可改**：

| 可以改 | 不可以改 |
|---|---|
| 换行、缩进、空行、行尾空白 | 任何一个字、标点、语序 |
| 剪切标记的位置与数量 | 段落里说了什么 |
| frontmatter（`status`、`title`、`updated`） | 把两段合成一句、删掉「废话」、补上缺失的标点 |

### 机器怎么保证

`raw.md` 第一次落盘时封存一次：

```bash
python scripts/check-knowledge/check_knowledge.py --capture-seal 2026-09-29-01
```

封存的是**正文去掉剪切标记、去掉所有空白之后的 sha256**，写进
`scripts/check-knowledge/captures.json`。于是：

- 改一个标点 → 摘要变了 → `captures` 检查失败，提交被拦。
- 重排段落、重新切段、编辑器删掉行尾空格、pre-commit 的 fixer 改格式 → 摘要不变，照常通过。

**它保证什么、不保证什么**：它保证 `raw.md` 一旦封存就不再被改。它**不**保证 `raw.md` 与你当时
说的话一字不差 —— 那一步靠转录纪律（`/intake` 要求逐字抄写，并把正文回显给你核对一次）。
封存后若内容真的变了，命令**拒绝**自动盖过去，必须有人显式处理：这是检查在工作，不是它坏了。

## triage.md：一段一行，谁都不许掉

| 列 | 内容 |
|---|---|
| ID | 段号 `S01`…，与 `raw.md` 的剪切标记一一对应、顺序一致 |
| 摘要 | **整理者的话**（不是原话）。原话只住在 `raw.md`，所以这里可以放心缩写、可以写人话 |
| 处置 | 下面词汇表里的七个词之一 |
| 去向 | `decide` / `clarify` / `execute` 三段必须落到一个真实去处；其余留 `—` |

### 处置词汇表（封闭）

| 处置 | 含义 | 需要去向 |
|---|---|---|
| `decide` | 要先做决策才能动：新能力、不可逆变更、有权衡要算 | 是（`DEC-xxx`） |
| `clarify` | 得先问你一句才能归位 | 是（问完之后） |
| `execute` | 小而明确，直接进方案 | 是（方案 / 文档 / 目录路径） |
| `defer` | 认了，但先不做 | 否 |
| `reject` | 明确不做 | 否 |
| `dup` | 另一段已经覆盖它 | 是，写 `#Sxx` |
| `noise` | 没有信息的填充 | 否 |

七个词是封闭的：写别的会被检查拒绝。这样「漏掉一个想法」没有藏身处 —— 每一段要么有去处，
要么被显式地搁置。

## 收尾

所有 `decide` / `clarify` / `execute` 的段都有去处之后，把 `raw.md` 的 `status` 改成 `closed`。
`closed` 之后再出现「决而未决」的段，检查会问它去哪了。

## 检查（`captures`）

1. 正文摘要与封存一致 —— 原话没被改过。
2. 剪切标记为 `S01..Sn` 连续升序 —— 段与段之间没有归属不明的字。
3. 每段在 `triage.md` 恰有一行，处置在词汇表内 —— 没有段被丢掉。
4. 全仓任何 `id#Sxx` 引用都能解析到真实存在的段 —— 方案和工单不会指向幻觉。
5. `status: closed` 时没有「决而未决」的段。
6. `knowledge/inbox/` 下的每个 capture 都在 `captures.json` 里有封存记录，反之亦然 —— 封存不会活得比它
   冻结的东西更久。

`raw.md` 是全仓唯一豁免散文检查的文件（`refs` 不校验它）：它的内容不归我们编辑，而一个它
不可能通过的检查，等于一个没人能修的检查。
