# S05 — 发布后兼容清理

> 状态：deferred
> Issue：TBD（正式发布满一个周期后再创建）
> Owner：待认领

## 1. 这一段要解决什么

- 问题：DEC-081 为平滑迁移保留了 `/auth/sms/register` 与旧 `purpose=register` /
  `reset_password`，但不能永久保留双入口和废弃参数。
- 可观察结果：确认旧调用为零后，移除兼容端点/参数、更新测试和文档，认证入口只剩一条。
- 不做什么：不在发布周期结束前删兼容；不用开发期调用量替代生产证据。

## 2. 边界与契约

- 涉及对象：`/auth/sms/register`、`send-code` 的旧 `purpose`、注册页/登录页旧调用、
  `AuthCard`、`useSmsCode`、认证测试。
- 会改的契约：认证 API 面、错误码与老客户端行为；必须按行为变更处理。
- 开工前必须确认：
  - 正式发布时间；
  - 生产旧端点/旧 purpose 的调用量；
  - 是否仍有老客户端依赖，以及有没有明确的强制升级窗口。

## 3. 执行路径

1. 收集生产调用证据：旧端点、旧 purpose、旧参数各自是否为零。
2. 若仍有调用，延长保留周期并记录复议条件；若为零，写一条移除兼容的新决策。
3. 删除旧端点/参数和前端兼容分支，更新测试、类型、文档与对象认知。
4. 跑认证定向测试与发布清单；把删除前后的调用证据和测试结果写入本切片。

## 4. 验收与证据

- 机械验收：认证定向测试通过；废弃端点/参数在代码与文档中不再出现。
- 行为验收：主流程「验证码即注册/登录」仍可用；老客户端在升级窗口中按约定降级。
- 证据位置：本文件 §5，附生产调用查询结果和测试摘要。
- 回退方式：保留一个发布窗口的 revert 路径；删除前确认可以恢复旧路由而不破坏数据。
