# Intent — 产品缺口 P0+P1 上线前闭环

> WorkItem：`W-20261014-01`

## 原始来源

- [`knowledge/plans/产品缺口-2026-10.md`](../../plans/产品缺口-2026-10.md)
- [`knowledge/plans/产品缺口实施方案-2026-10.md`](../../plans/产品缺口实施方案-2026-10.md)

## 问题

产品缺口方案中的 P0 与 P1 功能已经落到代码，但还存在三类没有闭环的事实：服务依赖验收未在
真实环境执行；前端行为缺少明确的测试载体；对象认知、后续产品决策和发布后兼容清理没有统一
的持续控制面。继续靠聊天记录推进会同时支付重新理解、寻找前沿和核对证据的成本。

## 期望结果

在正式上线前，用一份可交接的 WorkItem 把 P0/P1 的实现结果、剩余验收、当前前沿、决策和证据
连起来，使每一个后续会话都能从同一入口继续，不需要重读全部产品文档。

## 成功判据

1. 服务依赖验收、前端验收载体、对象认知、延后决策和发布后清理各有唯一处置；
2. 每张切片的完成都有可复跑证据或明确的环境阻塞说明；
3. GitHub Issue 是认领、依赖和关闭的唯一真相，文档只保存意图、上下文和证据；
4. 未决产品取舍有决策或带复议条件的 defer，不以「后续再看」消失；
5. WorkItem 收敛后，总纲的当前前沿和效果仪表盘与实际证据一致。
