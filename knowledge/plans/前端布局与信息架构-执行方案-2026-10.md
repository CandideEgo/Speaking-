## S1 · 排序语义：让 UI 说实话（BUG-01）

**问题**：首页一旦动了分类或难度，数据源就切到 `/browse/feed` 且不传 `sort`，后端默认 `latest`（`backend/app/api/v1/browse.py:89`），而下拉里仍写着「推荐」。

**为什么不能走后端补排序**：`browse.py:70-89` 只实现 `weekly_favorite / favorite / hot / latest` 四种，**没有 `recommended`**；`usePlatformFeed.ts:31-33` 的注释也写明「recommended 是 client-only」。所以只能让 UI 说实话。

**改哪里**

1. `frontend/src/hooks/usePlatformFeed.ts`
   - 把现在写在 fetcher 闭包里的 `isHomeDefault`（`:167-171`）提到外层计算一次；
   - 新增派生值并**加入返回值**：
     ```ts
     const effectiveSort: FeedSort = isHomeDefault
       ? "recommended"
       : sort === "recommended" ? "latest" : sort;
     ```
   - 说明：**不要改 URL**。URL 里保留 `sort=recommended` 是有意的——用户把筛选清回「全部」时应当回到个性化推荐流。
2. `frontend/src/components/home/HomeFilterBar.tsx`
   - 触发按钮的文案（`:146-149`）与下拉项的选中态（`:152` 附近）改用 `effectiveSort` 而不是 `sort`。

**可选增强**（不属于本步验收）：`sort === "recommended" && !isHomeDefault` 时，在面板底部加一行 12px muted 提示「推荐流仅在无筛选时可用」。

**验收**
- 首页选任意分类或难度 → 下拉触发按钮上写的是**「最新」**，面板里打勾的也是「最新」；
- 清回「全部 + 全等级」→ 回到「推荐」，且数据来自 `/recommendations/home`；
- `home-sort.spec.ts` 仍绿（**硬约束**：`aria-label="排序方式"`（`:152`）不能改，`home-sort.spec.ts:21,37` 与 `watch-return.spec.ts:38` 依赖它）。

```bash
npm run check && npm run test:e2e -- home-sort
```

**风险**：用户选了「推荐」却看到「最新」，可能困惑。这是"说实话"的代价，比继续骗人好；如需更柔和，再加提示行。

## S2 · 容器统一（gutter 不变）

**目标**：让首页 / 频道 / 浏览 / 搜索 / 排行榜 / 播放页在宽屏上铺开，并让**顶栏与内容左右边界严格对齐**。

**⛔ 两条硬约束（写错会破 INV-024，而 640–1023px 档没有任何 e2e 兜底）**
1. **gutter 一个字都不能改**：播放页画框与当前句卡靠 `-mx-4 sm:-mx-7`（`watch/[id]/page.tsx:1000`、`:1141`）精确抵消容器 padding 实现全出血；容器 padding 一改，640–1023px 档出血就错位、横向溢出。


2. 把 `container-page` 换成 `container-wide`（**其余 class 不动**）：

**验收**
