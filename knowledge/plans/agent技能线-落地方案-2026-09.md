## 0. 结论（先看这三条）

1. **不移植那套技能集。** 本地已经是同构且更严的实现：`.agent/`（热层，按 tier 计费）+ `knowledge/wiki/`（冷层，8 KB/页 glob）+ `docs/`，外加 `scripts/check-knowledge/check_knowledge.py` 八道门 + 一道 advisory。Matt 那边对应物是「技能自带 frontmatter 门禁 + 无自动 eval」，本仓多一层机器检查。
2. **真正缺的是三格，不是一整套流程**：① 文档引用了本地不存在的能力（`/code-review`、`/triage`）；② handoff 已经当票在用，但票上没有「演示路径」和「阻塞边」，依赖图被迫手写在计划正文里、无法机器校验；③ 承认过「仍未机器化」的两处（热层行形状 S2、`stale` 升级为失败 S6）可以先收掉一半。
3. **借的东西按本仓的判据落地**：能变成检查的写成检查（门或 advisory），变不成检查的写进 `knowledge/wiki/` 冷层，绝不写进热层。

## 2. 三个真实缺口（带证据）

### 缺口 A — 文档引用了本地不存在的能力

- `WORKFLOW.md` §6 把 `/code-review`（Standards + Spec 双轴）写进了「对抗开发流程」和附录 B 快速参考卡，§1 决策树也用 `> 200 行 → /code-review` 收尾。
- 实际可用的审查能力是 `open-code-review`（已装，`ocr` CLI，`knowledge/wiki/problems/review-fix-failure-modes.md` §4 就是它的使用复盘），**没有** `/code-review` 这个斜杠命令。`/verify` 同样不存在。
- `docs/agents/triage-labels.md` 声称「the skills speak in terms of five canonical triage roles」——当前没有任何技能会读它；而 `WORKFLOW.md` §7 用的是另一套标签（`bug` / `feature` / `refactor` / `security` / `blocked`）。同一个事实两个家，且都没接上执行者。

### 缺口 B — handoff 是票，但票上没有验收面和依赖边

本地已把 handoff 当工单用（S1…S8 逐票一个文件），但：

- 依赖图只能写在计划正文（`词汇训练与播放页返回-剩余分片计划-2026-09.md` §1.1 的箭头图）——**机器看不见**，改一次依赖要改两处。
- 模板没有「完成后我能 demo 什么」这一格。Matt 那边拿它防**水平切分**（按 schema/API/UI 分层切，最后一刻才集成）；本地实测教训同源：一份 26 票按层切的拆解，四分之三返工。
- 没有「阻塞项全 done」的 frontier 视图，`state.md` 得手工维护哪些 handoff 待归档。

### 缺口 C — 两处自己承认「未机器化」

`.agent/state.md` 明写：「仍未机器化：热层行形状（S2）、stale 命中承重模块升级为失败（S6）」。`scripts/check-knowledge/README.md` 的「The write standard」也写了同一句：行长 / 一行一断言 / 段落 < 4 行 / 热层无代码块「`check_knowledge.py` cannot read any of this yet」。

其中「一行一断言」需要人读，机器验不了；但**行长、段落长、热层代码块、跨文件重复行**四项是纯文本属性，可验。

### P1 — 给 handoff 补两格（票=工单）

改 `../../.agent/handoffs/README.md` 模板，加两行字段：

```
- 演示路径: <完成后我能演示什么，一句话；水平切分在这里暴露>
- 阻塞: <本票依赖的 handoff 文件名；无依赖写「无」>
```

- `Planner acceptance` 保留并明确它就是**完成判据**。
- `../../.agent/owners.md` 规则区加一条：**一张票一个 session，票之间 clear**；并声明「阻塞项未全部 done 的票不得派发」。
- 成本：`handoffs/README.md` 与 `owners.md` 都不在 `knowledge-budget.json` 的任何 tier 里，也不在 `files` 里，**不触门禁**；只增加冷层读取量。

### P2 — 新增两个检查（P1 的机器化）

`scripts/check-knowledge/check_knowledge.py` 已有 `CHECKS` / `ADVISORY` 两个 tuple（见 801–802 行）与统一的 `-> list[Violation]` 签名，加检查是局部改动。

**`handoff`（门，进 `CHECKS`）**：

1. `.agent/handoffs/*.md`（除 `README.md`）必须含模板要求的小节，`演示路径` 非空。
2. `阻塞` 指向的文件必须存在（复用 `refs` 的路径解析即得 dead-link 检测）。
3. 依赖无环；环上每个文件都报。
4. 打印 frontier：阻塞项全部 `Status: done` 的 handoff 列表。

**`shape`（advisory，进 `ADVISORY`，仿 `stale` 只打印不阻断）**：

1. 热层五个文件（tier 成员）：行长 > ~160 字符、段落 ≥ 4 行、出现代码块。
2. 知识层内**完全重复的行**（跨 `.agent/*.md` 与 `knowledge/wiki/**`，`knowledge/archive/` 豁免）——这是「一个事实一个家」的唯一可机器形式，也是 Matt 列的第一失败模式。
3. 理由与 `stale` 一致：写作瞬间的墙只会买到更短的句子，不会买到更少的事实（DEC-062）。想当门用的人自己加 `--strict`。

工程注意：该目录**不受 ruff 管辖**（`scripts/check-knowledge/README.md` 末尾明说），手写 PEP 8；hook 无需改，`knowledge-check` 的 `files:` 正则已覆盖 `.agent/`、`knowledge/wiki/`、`.claude/skills/`；advisory 的 verbose 打印先例见 `../../.pre-commit-config.yaml` 的 `knowledge-stale`。

### P3 — 两条纪律进冷层（变不成检查的那部分）

| 借来的规则 | 落点 | 为什么落这儿 |
|---|---|---|
| **红灯反馈环闸门**：诊断前必须有一条「已跑过一次、能对这个 bug 变红、修好后变绿」的命令；建不出来就停下报告，不许猜 | `knowledge/wiki/guides/testing.md`（本地测试约定的家） | 是本仓已有教训的推广——`knowledge/wiki/problems/review-fix-failure-modes.md` §4 已写「先让它红、再让它绿」，只是还停留在「那次审计的经验」 |

## 4. 执行顺序与门禁

1. **`/decision-support`** → 入库一条 DEC：新增 `handoff` 门 + `shape` advisory，以及 §3 P4 的否决清单。（本仓 MUST：改流程/门禁前走决策）
2. P0 三项（纯文档，走「快速提交」或「标准开发」）。
3. P1（模板 + owners 规则），随后 **P2**（检查）——顺序不能反，先有约定才有校验。
4. P3 冷层文档。新 `knowledge/wiki/` 页若引用新模块，补一句 `python scripts/check-knowledge/check_knowledge.py --stamp-refresh --module <name>`。
5. **`/knowledge-maintain`**（跨模块变更后再提交，本仓 MUST）。
6. 收工验证：
   ```bash
   python scripts/check-knowledge/check_knowledge.py          # 期望 0 新违规
   python scripts/check-knowledge/check_knowledge.py handoff shape
   pre-commit run knowledge-check --all-files
   ```
   新检查上线后必须先跑一次全量，把存量违规交给 `knowledge-baseline.json`（`--baseline-update`），否则会一次性卡住所有提交——这是本仓唯一的「接受存量违规」通道。

## 5. 成本与风险

- **门禁风险**：`handoff` 是门，存量 handoff 文件（含 `.agent/handoffs/2026-09-27-*.md`）大概率缺「演示路径」→ 用 baseline 吸收，或先补齐现有两三条。
- **误报风险**：`shape` 的「重复行」对空行、`|` 表格分隔行、`---` 会天然重复——须豁免空行与纯标点行，否则第一版就是噪音。宁可先窄（只报长度 ≥ 12 字符的完全重复行）。
- **字节成本**：P1 的两处不在 tier 内，P3 的新 `knowledge/wiki/` 页受 8 KB glob 约束；热层不动，`tier:session_total` 不涨。**若哪一步需要动热层，那是走错了层**——按 `scripts/check-knowledge/README.md` 的「热文件一行 + 指针」处理。
- **不变量**：全案无代码删除，不触 `invariants.json`；不改 `modules.json`（除非 P3 的新页要引用新模块）。
