## 2. 根因

### 2.1 三个现象共用一个结构问题

壳层和顶栏满宽，内容却被各自封顶在 1320 / 1280 并居中，两个页面宽度还不一致。于是屏幕一宽只剩留白（2560 屏各留 620 / 640px），且**顶栏贴边、内容居中**本身也是视觉问题；全仓没有任何大屏规则。

### 2.2 铺满 ≠ 好，密度才是

YouTube 在 2560 屏上是 5 列 × 约 450px；我们目前 4 列 × 298px。若直接铺满而保持 4 列，每列会变成 566–606px，卡片大得离谱。**正确做法是让列数跟着宽度长**，让单卡宽度落在 260–400px。

### 2.3 跟读区两块都是「盒子里装空气」

- 上面那块（`watch/[id]/page.tsx:1158-1164`）：`flex items-start gap-4` 的左边是一个 `<div className="flex-1 min-w-0">`，**而它绝大多数时候是空的**（只有字幕隐藏模式才有一行字）。`flex-1` 吃掉全部剩余宽度，右侧 `shrink-0` 的按钮组被顶到最右——用户说的「前面是留白」就是这个空 spacer。外面还套着 `p-5`。
- 下面那块（`ShadowingHistory.tsx:21-32`）：无论有没有数据都渲染，空态是 `mt-3 pt-3 border-t` 里一行 11px 小字，被大卡边框框成第二个空框。

### 2.4 长句裁掉的是中文，不是英文

`CurrentSentenceCard` 只有一层 92px 高度上限，英文块 `leading-8` 不限行数，中文块排在后面：英文 2 行 = 64px + 2px + 中文约 21px ≈ 87px 刚好塞下；**英文 3 行 = 96px 越过 92px，中文整块被裁掉。**

⚠️ 这个 92px **不是随手写的**：`knowledge/plans/移动端播放页-壳层控制条-落地方案-2026-10.md` 落地差异第 3 条写明"超长句（英文 3 行）截断，宁可不撑高卡片"——DEC-069 / issue #31 的刻意取舍，被 INV-021 的 e2e 看管。修法必须是**换掉被牺牲的那一项**（改成裁英文、保中文），不能取消上限。

## 3. 方案 A：宽度与容器（先做，其余都依赖它）

### 3.1 容器统一 ← 这里 v1 写错了，以下是修正版

**关键约束（v1 漏掉）**：播放页的画框和当前句卡靠 `-mx-4 sm:-mx-7`（`:1000`、`:1141`）**精确抵消容器的 `px-4 sm:px-7`** 来实现全出血。容器的 gutter 一旦变动，640–1023px 档（`isMobile` 仍为 true）出血就会错位、横向溢出，破 INV-024。而**这一档没有任何 e2e 覆盖**（移动端 spec 只跑 375/390/414）。

所以：

```css
/* @theme 里，紧挨 --max-width-page */
--max-width-wide: 2400px;

/* @layer components */
.container-wide { @apply max-w-wide mx-auto px-4 sm:px-7; }   /* ← gutter 与 container-page 完全一致 */
```

- **gutter 一个字不改**（`px-4 sm:px-7`），出血抵消继续成立，640–1023 零风险；
- 只放宽 `max-width`，并把 `.container-wide` 应用到首页 / channels / channels\[slug\] / browse / search / rankings / 播放页；
- **顶栏要一起套这个类**（把 `TopBar.tsx:275` 的行内内容包一层 `.container-wide`），否则 >2400px 的屏幕上容器居中、顶栏满宽，又错位——v1 的验收标准（"2560 下左右留白与顶栏 padding 严格对齐"）在 v1 的设计下**根本不可能达成**（容器 2400 居中 → 左边界 112px；顶栏满宽 `px-8` → 32px，差 80px）。
- `.container-page`（1320）**保持不动**，18 个页面零影响——v1 说要"顺带改顶栏 gutter"，那会让顶栏和这 18 个页面**从对齐变成错位 4px**，已撤销。

### 3.2 网格列数自适应

首页网格字符串 `sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4` 在 `page.tsx` 里 **3 处**（`:101` Suspense 骨架、`:155` 主网格、`:177` loading），但**全仓共 10 处 / 4 个文件**（还有 `browse/page.tsx:42,125,139`、`channels/[slug]/page.tsx:101,176`、`favorites/page.tsx:120,141`）。只改首页会让同一屏宽下首页 5 列、`/browse` 4 列。

```tsx
<div className="grid gap-6 grid-cols-[repeat(auto-fill,minmax(min(260px,100%),1fr))]">
```

- `min(260px,100%)` 防窄容器横向溢出；**不要换成 `auto-fit`**（末行只剩 1 张卡时会被拉成满宽，比留白难看）。
- 实际列数：2560 屏（容器封顶 2400，内容 2336）= **8 列 × 271px**；1275 屏 = **4 列 × 285px**；375 屏 = 1 列 × 343px。v1 写的"6–7 列"是算错的。
- 已知代价：`auto-fill` 会保留空轨道，末行不满时右侧留白（2560 屏 / 49 个视频 → 末行 1 张卡 + 7 个空轨道）。这是 `auto-fill` 的固有行为，也是 YouTube 同款，**接受**。
- **必须同步改的骨架**（否则加载前后列数跳变）：`page.tsx:101,177`、`(main)/loading.tsx:5,10`、`rankings/loading.tsx:3`、`vocabulary/sets/[id]/loading.tsx:3`、`common/ShellSkeleton.tsx:31,44,54`、`common/SkeletonCard.tsx:83`、`browse/page.tsx:42,125,139`、`channels/[slug]/page.tsx:101,176`、`favorites/page.tsx:120,141`。

### 3.3 播放页：铺满要配高度护栏

视频框是 `aspect-video` 且**没有高度上限**（`watch/[id]/page.tsx:993-1006`）。容器放宽后左列可达 1500px+，16:9 就是 850px+ 高，必定把当前句卡挤出视口。

**v1 的两个错误，修正如下：**

1. **v1 把 `max-w-[calc(...)]` 写在共享 class 串的前缀里**，对 `isMobile` 分支同样生效（tailwind-merge 不会拿掉它），横屏/矮视口会把出血画框压窄 → 破 INV-024。**必须显式门控 `!isMobile`。**
2. **v1 只夹画框、不夹当前句卡**，桌面两端左右边界不再重合（1280×720 下画框 818px 居中、卡 876px，错开 29px）。而 `mobile-current-sentence-card.spec.ts:300-301` 正是断言"卡与画框同宽、左对齐"——今天在 1280×900 跑所以没挂，不变量其实已被破坏。**上限必须加在同时包住「画框 + 当前句卡」的包裹层上，或者两者给同一条上限。**
3. 常量：v1 的 `260px` **少了约 30px**。按代码量，桌面 = 顶栏 64 + 容器 `pt-6` 24 + 页头 ≈76 + 句卡 `mt-3` 12 + 卡高上限 ≈114 = **290px**，再加 `env(safe-area-inset-top)`。**这个值必须由 e2e 实测校准，不要当定值写死。**

```tsx
// 包裹层（画框 + 当前句卡 一起）
<div className={cn(!isMobile && "watch-stage-cap")}>
  ...frame... ...CurrentSentenceCard...
</div>
// globals.css：.watch-stage-cap { max-width: calc((100dvh - 290px - env(safe-area-inset-top,0px)) * 16 / 9); margin-inline: auto; }
```

右栏从 `lg:grid-cols-[2fr_1fr]`（`:966-973`）改成 `lg:grid-cols-[minmax(0,1fr)_minmax(360px,420px)]`。v1 写的 `clamp(320px,26%,420px)` 在 1024–1700 这段主流宽度上会让右栏**比现在更窄**（1280 屏：405 → 320，−21%），字幕行换行更多；下界提到 360 才不会缩水。这是 v1 没记账的桌面副作用。

> ⛔ 约束：`isMobile` 分支（`w-screen` 出血、`-mx-4 sm:-mx-7`、sticky 钉顶、`display: contents`）一个字都不动。

## 4. 方案 B：首页信息架构

现状：`frontend/src/app/(main)/page.tsx`——问候 → 统计条 → 筛选栏 → 网格。

**v1 的四条判断经评审后修正如下**（原描述有夸大和不准确处）：

| v1 的说法 | 评审结论 |
|---|---|
| 「三种控件排成一行会被误读」 | **部分成立**。筛选栏 `<768px` 本来就是分行堆叠（`HomeFilterBar.tsx:229`），组间有分隔线（`:240`），两个下拉都有 `ChevronDown`。真正的问题更窄：**排序下拉的当前值「推荐」紧跟在「分类 ▾」后面，读起来像一个被选中的分类**（`:114`、`:146-149`） |
| 「一行里两个 N 个视频」 | **口径不同成立，"一行里"不成立**。两者分属统计条与筛选栏两个条，且筛选栏那个 <640px 不渲染（`:255`） |
| 「统计条没有主次」 | **只对三个数字成立**。右侧 CTA 是实心品牌按钮（`CompactStatsBar.tsx:73`），主位明确。**但 CTA 只在 `dueCount > 0` 时渲染（`:70`）**——零到期词的账号首屏没有任何主行动 |
| 「没有继续观看」 | **成立，且数据现成**。写入点活着：`PATCH /api/v1/learning/progress`（`backend/app/api/v1/learning.py:129-194`），前端每 10s 调一次（`frontend/src/hooks/useVideoPlayer.ts:692-715`）；`GET /learning/records` 已 join Video 并按 `last_accessed_at DESC` 排序（`learning.py:28-81`），`?page=1&page_size=1` 就是最近一条 |

**修正后的改法（只留真的该做的）：**

1. **先修排序语义，再把它升为主位**。`/browse/feed` 的排序真相是 URL，但首页动了筛选就切流且不传 `sort`，后端默认 `latest` 而 UI 仍写「推荐」（缺陷清单 BUG-01）。**把一个会说谎的控件放到首位是在放大问题**，所以 BUG-01 必须排在 §4 之前。
2. **给排序控件加限定词**：`推荐 ▾` → `排序：推荐 ▾`。这一条就能消掉「分类 ▾ 推荐 ▾」的连读误读，成本一行。
3. **三个统计数字各自加去处 + 定义零到期词的主行动**：`/vocabulary`、`/history`、`/profile` 都已存在，包一层 Link 即可；`dueCount === 0` 时给一个备用 CTA（去练习 / 去频道）。
4. **难度 pills 对齐既有约定**：`frontend/src/lib/cefrLevels.ts:1-11` 白纸黑字写着"所有面向用户展示难度的地方统一走这里的映射"，而首页（`HomeFilterBar.tsx:21-29,244`）是唯一违反者——`browse/page.tsx:100-103` 用了 `cefrWithExamHint`。
5. **「筛选」按钮 + 面板**：⚠️ 这是一块**真实的新增开发**，不是"收进一个按钮"。仓库里 `DropdownButton` 是 `HomeFilterBar.tsx:49-99` 的文件内函数（未 export），`components/ui` 与 `components/common` 下**没有** Sheet / Popover / MultiSelect / FilterPanel。且面板里 **「来源」「时长」两个维度后端不存在**（`/browse/feed` 只接受 `category / level / sort`，`backend/app/api/v1/browse.py:129-133`），多选还会破 URL 单值契约（`usePlatformFeed.ts:111` 是 `searchParams.get`）。**建议 v2 先只做「排序加限定词 + 统计数字加去处 + 难度标签对齐」，把筛选面板整体降级为独立一票。**
6. **统计文案的口径要先定义**：`17 个视频` 来自 `/learning/records` 的 total，而记录在**视频首次可播打开时**就建（`backend/app/services/video_service.py:196-213`），此时 `time_spent_seconds` 还是 0。改成「已学 17 个视频」之前必须先定口径（如按 `time_spent_seconds > 0` 过滤），否则是把模糊数变成错误标签。

## 5. 方案 C：播放页与跟读体验

### 5.1 当前句卡：换掉被牺牲的那一项

**不改 92px 上限**（DEC-069 的既有取舍），改成"英文让位、中文常在"：

1. 内层 `div` 改 `flex flex-col`；
2. 英文块加 `line-clamp-2 overflow-hidden`（`leading-8` ×2 = 64px）；
3. 中文块加 `shrink-0`；64 + 2 + 21 = **87px ≤ 92px**，正好落在原预算里。

⚠️ **v1 提的「展开」按钮已撤销**（评审否决）：`mobile-current-sentence-card.spec.ts:104-115` 用**卡底部 20% × 横向 75%** 作为"卡片空白"的点击探测点，断言点那儿切播放/暂停、不开词卡。卡内下 1/5 放控件会打红这条。若一定要展开入口，只能放在**计数器旁边（`top-2 right-3`）**或卡外。

⚠️ 另两点必须记账：
- `line-clamp` 会裁掉英文第 3 行起 `.now-sub-word` 的点击热区（热区靠 `inline-block -mb-1 pb-1` 的 4px 外扩），而 `mobile-inline-subtitle.spec.ts:216` / `mobile-current-sentence-card.spec.ts:214` 是靠 Playwright 可见性命中点词的。**被裁区域不可点，需要接受或另设计。**
- `CurrentSentenceCard` 是**移动端与桌面端共用的唯一一份**（INV-021）。第 1–3 步两边同时生效——**这属于"改移动端"**，需要用户明确点头；桌面专属的 `lg:max-h-none` 会再多一条平台分叉，本轮建议**不做**。

### 5.2 跟读区重设计 ← v1 的方案被评审换掉了

**v1 的问题**：那条"56px、两个按钮靠左"的控制条，在容器放宽到 2400 后左列可能 1580px 宽，"230px 内容躺在 1580px 行里"正是用户抱怨的留白换个地方复发；而且它漏掉了现有 5 个真实状态。

**v2 采用：把跟读变成当前句卡底部的一条整宽动作带（一张卡，一条线）。**

```
┌─ 当前句卡（唯一一张，画面正下方，INV-021 的那一份）──────────────┐
│  英文句 …                                                        │
│  中文句 …                                                        │
│  ─────────────────────────────────────（分隔线，仅桌面 lg:flex）  │
│  [   🎙 逐句跟读   ][   ● 录音本句   ]   ← 整宽 2 段分段控件      │
│  最近  [▶0:03 14:22✓] [▶0:08 14:19✓]  更多 →  ← 0 条时整行消失   │
└──────────────────────────────────────────────────────────────────┘
```

1. **删掉框 #2 和空的 `flex-1`**：`:1158` 那张卡整体移除，`ShadowingHistory` 移进动作带。
2. **动作带整宽**：`grid grid-cols-2 gap-1 rounded-pill bg-surface-card p-1`（复用 `components/ui/TabPills.tsx:60-88` 的视觉语言），每段 `flex-1`。宽屏不再有"内容躺空行"的观感。
3. **单框**：动作带与当前句卡**共用同一个外框**，两块之间只有一条分隔线——从"上下两个框"变成"一张卡一条线"。
4. **状态就地变形**，高度随内容、不预留空白。必须覆盖现有**全部**状态（v1 漏了后面 4 个）：

| 状态 | 证据 |
|---|---|
| 空闲 / 录音中 / 待评判 | `watch/[id]/page.tsx:1170-1212`、`:1249-1271`、`:1273-1327` |

### 5.3 其余体验项

- **进度语义统一**：`144 / 187`（句号，`:1151`）与 `13:19 / 17:43`（时间）并列容易被读成一个东西且天然对不上（`lib/subtitles.ts:11-29` 在句间空隙返回 `-1`）。建议控制条只显示时间、字幕区只显示句号。

## 10. 评审修订记录（v1 → v2，被改掉的硬错误）

1. **「移动端本轮不动」原本做不到**：§3.1 的 `sm:px-6` 会破坏 `-mx-4 sm:-mx-7` 的出血抵消（640–1023 档，零 e2e 覆盖）；§3.3 的 `max-w` 写在共享前缀里会落到移动端分支；§5.1 改的是共用卡。→ 前两条已改，第三条已在 §5.1 显式标注需用户点头。
2. **§3.1 的顶栏改法会制造新错位**：顶栏改 `sm:px-6 lg:px-8` 后，与仍用 `container-page`（`sm:px-7`）的 18 个页面差 4px，从对齐变错位。→ 撤销，改为"顶栏套 `.container-wide`、gutter 不动"。
3. **§3.1 的验收标准在自己的设计下不可能达成**（容器 2400 居中 vs 顶栏满宽，差 80px）。→ 已修正为顶栏共用同类。
4. **§3.3 的高度护栏会打到移动端、且只夹画框不夹卡**。→ 已改为 `!isMobile` 门控 + 夹住"画框 + 句卡"的包裹层；常量 `260px` 少算 30px，改为 290px 并注明需 e2e 校准。
5. **§5.1 的「展开」按钮会打红 e2e 的空白点击探测带**（卡底部 20%）。→ 撤销。
6. **§3.2 的列数算错**（说 6–7 列，实际 8 列）；**网格字符串实际有 10 处 / 4 个文件**，不是 3 处。→ 已修正，并补全骨架清单。
7. **右栏 `clamp(320px,…)` 会让 1024–1700 的右栏变窄 20%**。→ 下界提到 360px。
8. **§4 的四条判断中被夸大的部分**（筛选栏实际有分隔线与分行、统计条 CTA 本来就有主位、"一行里两个视频数"不成立）；**「看完」→「看清楚」不等**。→ 已按评审修正，并新增"零到期词无主行动""难度标签违反 `cefrLevels.ts` 既有约定""`已学` 口径未定义"三条。
9. **行号修正**：`CurrentSentenceCard.tsx:76` → **`:72`**；`globals.css:594` → **`:595`**（且 `.now-sub-en` 写的是 `leading-relaxed`，32px 来自 utility 的 `leading-8`）；`container-page` 使用面从"25 个页面"改为 **24 个文件 / 29 处**；`VideoCard.tsx` 的标题已是 `line-clamp-2`（`:165`）；`VideoBrief` **没有频道名**（`backend/app/schemas/common.py:28-38`），「继续观看」要展示频道得先补后端字段。
