# Testing
# Pinned: an open range let CI resolve a different stack than the one the suite
# is verified against, and for aiosqlite the two disagree in a way that breaks
# the job rather than a test.
#
# aiosqlite runs every connection on its own worker thread. In 0.20.0 that
# thread is a daemon; 0.22.1 has no daemon flag at all, so it is a normal
# thread. The suite never closes the test engines, so the thread outlives the
# session and the interpreter parks in threading._shutdown() forever. Symptom:
# CI reports "746 passed, 0 failed" and is then killed by the step's 10-minute
# timeout — confirmed with faulthandler, see pytest_sessionfinish in
# tests/conftest.py.
#
# The pytest pins below did NOT fix that hang (measured in CI) — they are here
# for the same general reason and are the combination the suite was verified
# against. Bump any of these and re-verify in CI, not just locally.
pytest==8.2.0
pytest-asyncio==0.23.7
pytest-cov==5.0.0
pytest-timeout==2.4.0
aiosqlite==0.20.0

# Linting & formatting

# Ruff's formatter can change its output between minor versions, so an open range

# 0.16.4 while pre-commit pinned 0.15.18. Bump both in the same commit.
