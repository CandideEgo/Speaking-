# Invariants

> Rules that must keep holding, and features that must not come back. Read this before changing
> code. If a change breaks one of these, the change is wrong — not the invariant.
>
> **本文件是规则的唯一正文**（`.agent/README.md` 的边界条款 1）。每条 INV 写「规则 + 为什么 + 强制方式」，
> 只留一行能定位的指针：后果在 AOCI 对应对象的 S 字段，事故经过、实测读数与被否方案在
> `knowledge/decisions.md`（DEC-xxx）或 `knowledge/wiki/problems/`。**不要**把叙述搬回这里。

**Enforcement coverage: 2 machine checks, 12 test suites, 1 known gap, 11 review-only.** The
`Enforced by` column is a to-do list: every `review` that could be a check, should be one. See
`scripts/check-knowledge/README.md` for the check layer.

## Architecture and boundaries

| ID | Rule | Why | Enforced by |
|----|------|-----|-------------|
| INV-001 | The GPU worker must not have DB access or OSS credentials | it runs on an untrusted GPU host; the boundary is the whole reason the pipeline is split into Head/GPU/Tail | runtime guard in [start_gpu_worker.py](../backend/scripts/start_gpu_worker.py), asserted by `TestGPUWorkerSecurity` in [test_pending_processing.py](../backend/tests/test_pending_processing.py) |
| INV-002 | Every Redis dependency must fail-open — never block or raise when Redis is unavailable | Redis is cache/lock/queue, not the source of truth; a cache blip must not take down the site | review (the limiter has an in-memory fallback and a test) |
| INV-003 | Video processing is admin/catalog-triggered only — there is no user-facing submit path | GPU/LLM cost must be driven by the operating rhythm, not by user demand | test — [test_architecture_invariants.py](../backend/tests/test_architecture_invariants.py) audits every state-changing video route for admin auth |
| INV-004 | Tailwind v4 is CSS-first — never create `tailwind.config.js` | v4 reads config from `globals.css`; a JS config is silently ignored and misleads the next reader | check — `paths` rule in [invariants.json](../scripts/check-knowledge/invariants.json) |
| INV-005 | AI calls go through `ai_service.py` or `services/translation/*`, never `AsyncOpenAI` directly in a route | one place to control cost, retries, logging and provider swap | check — ruff `TID251` `banned-api` in [pyproject.toml](../backend/pyproject.toml) |
| INV-006 | Runtime AI calls happen only in the video pipeline (translation + word-note prewarm) | user paths must not carry per-request LLM cost or latency | review (INV-005 blocks the easy bypass, not a route that calls `ai_service` directly) |
| INV-007 | Word gloss has no live-LLM fallback — on cache miss it returns empty fields | a fallback would silently reintroduce per-request LLM cost on the hottest path | review |
| INV-008 | Payment is disabled for ICP compliance — redemption codes are the only channel | regulatory, not technical | review |
| INV-009 | `with_for_update` row locks are required for redemption and payment atomicity | concurrent redemption must not double-credit | test — `test_celery_tasks_pg.py` covers the `skip_locked` semantics of the redeem/order beats |
| INV-010 | Notification dedup is non-atomic (check-then-insert) | deliberate: notification data is low-stakes, and the alternative serialises a high-write table. Rare concurrent duplicates are the accepted cost | review — do not "fix" this without re-reading DEC-010 |
| INV-011 | Transcription hallucination detection runs at callback time and FAILs the video, stopping the pipeline | hallucinated subtitles reaching learners is worse than a stuck video | test — `TestTranscriptionQuality` in [test_quality_safety_net.py](../backend/tests/test_quality_safety_net.py) |
| INV-012 | The translation quality gate runs after batch translation; WARN logs and continues | transient API failures often clear on retry, so aborting would be premature | test — `TestTranslationQualityGate` in [test_quality_safety_net.py](../backend/tests/test_quality_safety_net.py) |
| INV-013 | Re-running `finalize_video` computes `word_levels` only when it is `None`, preserving manual overrides | re-processing must not destroy human work | **known gap — unenforced.** The guard is inlined in the "annotating" step of [video_processing.py](../backend/app/tasks/video_processing.py); `TestWordLevelsPreservation` only checks DB round-tripping. Extracting the decision from the Celery task would make it testable |
| INV-014 | LearningEvent emission must be non-blocking (try/except, logged, never raised) | analytics must never break the user-facing flow that emitted it | review |
| INV-015 | LearningEvent and BehaviorEvent stay separate models | different query patterns, retention and nullability; merging loses both | review |
| INV-016 | Video media is served from the backend's local media volume; covers are localized at ingest | rendering must not depend on external CDNs, and range requests need the local router | review — see `knowledge/operations/MEDIA-TOPOLOGY.md` |
| INV-017 | New frontend components use semantic tokens, not hardcoded colour values | dark mode is a single `.dark` variable block; hardcoded colours opt out of it | review |
| INV-018 | Anonymous users are denied media, detail and shadowing for any non-`is_demo` video | the login wall is a product decision that survived the free-tier change | review |

## Mobile watch page — the shell owns geometry, the frame owns attention

Rules for `≤1023px` on `/watch/*`. Why they exist, the measured evidence and the rejected
alternatives are DEC-069 / DEC-070; each rule's object-level consequence is in the AOCI entries for
the components named below.

| ID | Rule | Why | Enforced by |
|----|------|-----|-------------|
| INV-019 | **Bottom rows of the shell are in-flow, never `fixed`.** `MobileTabBar` and — on `/watch/*` — `WatchBottomBar` (`data-shell-bottom-bar="watch"`) are the shell's last in-flow row; safe-area padding belongs to the shell alone (`MainLayoutInner`'s `env()` padding), never to the bar. `useSheetGeometry` resolves "shell's last row" as `[data-shell-bottom-bar="watch"] ?? [data-testid="mobile-tab-bar"]`, first hit wins, and falls back to the visual-viewport bottom on desktop (neither renders) | on iOS Safari `fixed` anchors to the **layout** viewport (= `100lvh`), so a fixed bottom bar sits 40px below the visual viewport whenever the address bar is shown（真机实测：45px 的标签正好压在地址栏上沿）；browser-mode `viewport-fit=cover` is a no-op there (insets stay 0), so shell `env()` padding only bites in standalone / cutout Android。其它仍 `fixed bottom` 的浮层（考试交卷栏、迷你播放器）共担同一风险 | test — [viewport-height.spec.ts](../frontend/e2e/viewport-height.spec.ts) asserts the bar is not `fixed`, is ≥44px tall, and sits flush with the shell's bottom edge; [mobile-watch-chrome.spec.ts](../frontend/e2e/mobile-watch-chrome.spec.ts) §2 asserts the same for the watch-page bar |
| INV-020 | Shell and full-page heights use `dvh` (`h-dvh` / `min-h-dvh`), never `vh` | `100vh` on iOS Safari is the address-bar-**hidden** height — 40px taller than the visual viewport (真机实测 790 vs 750), so it pushes 40px of content out of sight | test — same spec asserts shell height == `100dvh` == `innerHeight` and no document overflow |
| INV-021 | **The current sentence renders exactly once**, in the current-sentence card (`CurrentSentenceCard`, `[data-testid="current-sentence-card"]`) **directly below the frame** — mobile and desktop alike. `≤1023px`: flush with the frame's bottom edge (0 gap), no border, no radius, no collapse toggle (R5「齐平字幕带」, DEC-070); desktop keeps the 12px gap + radius + border. `[data-testid="video-frame"]` holds zero text and zero clickable overlays | two renderings of the same sentence split the tap hotzone, leaving no single anchor for tapping a word; the in-frame copy also covered the speaker's face (414×896 first screen: 776px total, transcript only 76px). The anchor moved from the in-frame subtitle to the card, the reason (exactly one anchor) did not change | test — [mobile-current-sentence-card.spec.ts](../frontend/e2e/mobile-current-sentence-card.spec.ts) asserts count 1 at 414 and at 1280, zero non-empty text nodes in the frame, and that `.now-sub-word` opens the sheet for the tapped word; [mobile-inline-subtitle.spec.ts](../frontend/e2e/mobile-inline-subtitle.spec.ts) asserts the card sits flush (gap in the legal 0…16px window, R5 = 0), the hotzone lives only in the card, and the frame stays text-free; [mobile-watch-chrome.spec.ts](../frontend/e2e/mobile-watch-chrome.spec.ts) §1 counts `frame-title` / `frame-back` / `level-selector` / `controls-bar` / `thin-progress` / `burn-subtitle` as 0 |
| INV-022 | **Both new mobile overlays are anchored in one band.** Top edge = frame's bottom edge (0 gap, never into the frame; drops to the frame's bottom edge when the frame is too low to hold them). The word card (`WordCardSheet`) is **content-height** (`max-height` = bottom-bar top − top edge; never full-screen), the shadowing drawer's bottom edge = the shell's last in-flow row top (INV-019). Neither may change the player's geometry. **Accepted cost** (照账接受, DEC-069/070): because the card's top edge is still the frame's bottom edge and R5 removed the gap, the word card covers the current-sentence card completely — restoring it would be a new decision, not a bug fix | expanding must never push the player out (the one non-negotiable constraint of that round); a top edge above the frame's bottom edge would both cover the picture (INV-024) and hide the tap/read anchor. `useSheetGeometry` therefore listens for `scroll` in the **capture** phase (the scroll container is `main#main-scroll`, `window.scrollY` is always 0) and recomputes on `resize` (both device rotation and address-bar movement are resizes); a hardcoded card height would stretch it into a full-screen white board | test — [mobile-wordcard-drawer.spec.ts](../frontend/e2e/mobile-wordcard-drawer.spec.ts): at 375×812 the card/drawer top edge ≥ frame bottom edge, card bottom ≤ bottom-bar top and not bottomed out, drawer bottom flush with the bar, and the `video` rect is pixel-identical before/after expanding; recomputed at 390/414; handle-drag >64px closes, action buttons are 44px. §7-7 / §7-6b write "the card covers the current-sentence card" as the accounted assertion |
| INV-023 | **Follow mode means the frame itself sticks to the top.** Judged by a **zero-height sentinel** at the head of the scroll container crossing the container's top edge — **never measure the stuck element itself**. Form: the frame `sticky top-0` against the bottom of the watch page's 44px top bar (= `main#main-scroll` top edge) — no shrink, no fly-away, no disappear; reversible (scrolling back to the top releases it) | ① measuring the stuck element can never answer "was it pushed up": sticky pins `getBoundingClientRect().top`, so the check flips true→false→true and oscillates between sticky and static (observed: frame top flipping between 64 and −36). ② `IntersectionObserver` misses jump-scrolls (a transcript click scrolling to a sentence does not fire false→false). ③ sticky's range is its containing block: on a 490px left column the remaining travel (635px) is less than the scroll limit (707px), so the last ~72px drag the frame away — hence `display: contents` on the mobile left column, making the frame a grid item of the whole grid | test — [mobile-pip-scroll.spec.ts](../frontend/e2e/mobile-pip-scroll.spec.ts): sticks at the top, not one pixel smaller, still flush at the scroll limit (the regression the old implementation failed), keeps playback progress across the switch, releases on scrolling back, never covers the bottom bar (INV-019); the paired first-screen / scrolled cases live in [mobile-inline-subtitle.spec.ts](../frontend/e2e/mobile-inline-subtitle.spec.ts) |
| INV-024 | **`≤1023px`: the first screen is the frame.** The frame bleeds full width (`w-screen`, x=0) with its top edge flush with `main#main-scroll`'s top edge — the page header does not occupy a single pixel above the player. The title lives in the shell's top bar (`WatchTopBar`, 44px: back / title / level / ⋯); the old header row and the action row are not in the frame (mobile actions were deleted, then moved into the ⋯ sheet). The layer-order lesson about `z-20` is **void** — it was written for in-frame overlays, and the frame now holds none | `w-full` computes from the column width, so negative margins only move it: full bleed needs an explicit `w-screen`. The earlier failure mode was a mobile layout rendered with desktop numbers — 375×812 put the frame at y=166 with only 107.9px of picture visible (prototype `B2-tap.html`: x=0, y=166→frame top at the shell, 128.9px visible) | test — [mobile-player-shell.spec.ts](../frontend/e2e/mobile-player-shell.spec.ts): at 375 the frame is x≈0 / width ≈ viewport / top edge == `main#main-scroll` top edge (== the 44px bar's bottom), the bar carries title and level selector, the frame holds zero text and zero overlays, `mobile-actions` is absent, ≥120px of picture is exposed, no horizontal overflow, and the new back button `[data-testid="watch-top-back"]` is 44×44, centre-hits itself, and leaves the page; recomputed at 390/414/700, and at 1280 the `h1` is back, the frame does not bleed, and there is no two-column watch layout |
| INV-025 | **The watch chrome store (`WatchChromeProvider`) carries only stable references or ref-read values.** Anything whose closure reads component state (`currentSubtitleIndex` and friends) must be mirrored into a ref **before** entering the store | the first `onNext` passed a per-render closure reading `currentSubtitleIndex` while the chrome memo's dependency list held neither the closure nor the index, so the shallow compare saw "unchanged" forever and a **stale closure stayed resident** (measured: at 10/190 one press jumped back to 2/190, then stopped responding). The test is "does this function change with component state", not "is it a function". **Counter-example**: adding `currentSubtitleIndex` to the memo's deps also fixes it, but re-renders the shell four times per sentence, against the store's low-frequency contract | test — [mobile-sentence-nav.spec.ts](../frontend/e2e/mobile-sentence-nav.spec.ts) case A presses "next" three times and asserts `after > before` each time; case B is the symmetric control. Before the fix the run stopped at sentence 9 and one press jumped **back to sentence 2** (9 → 2). Discrimination comes from the **first** press reading the mount-time closure (no dependency changed up to it), not from avoiding playback toggles mid-run — the interference to avoid is opening the ⋯ sheet, switching level, or shadowing |

## Removed features — do not reintroduce

Each was removed for a reason; the reasoning lives in the cited ADR / `decisions.md` entry.
INV-003's test covers the route-level part of this list.

- AI speaking scoring (`speaking_service.py`, `rubrics.py`, `speaking_alignment.py`) — ADR-0002
- Speaking dashboard metrics (streak / goals / stats) — ADR-0003
- Community UGC (posts, likes, comments, follows, reports) — ADR-0012
- User-facing UGC video, submit-URL, fork / propose-back · AI learning plan · AI assistant and
  video comments · Live AI word-card definitions (per-request LLM cost, see INV-007) — DEC-025
- Pro paywall UI (`/upgrade`, `/pricing`, `/redeem`, `/checkout`) — DEC-037

Dormant-but-present, do not extend: `ai_service.py`'s `generate_practice_questions`, the
`GET /vocabulary/{id}/enrich` endpoint with no frontend entry point, `learning_plan.py`'s 410
endpoints, the `RedeemCode` / `plan` tables, and Video's UGC columns (`forked_from`, `auto_publish`,
`review_status`).

> Shadowing is **not** a removed feature. AI scoring of it is gone (ADR-0002), but recording
> persistence is active (ADR-0013).
