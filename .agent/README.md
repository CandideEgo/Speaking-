# 心智系统

这份文件只定义“事实放在哪、何时相信、谁来维护”。具体工具流程属于对应技能，不写在这里。

## 三层

| 层 | 位置 | 承载内容 | 读取方式 |
|---|---|---|---|
| L0 对象认知 | 机器认知卷及其状态目录 | 单个受管理对象的身份、关系、契约和改动后果 | 按需调用对象认知技能；不把流程放进常驻规则 |
| L1 热层 | `AGENTS.md`、`CONTEXT.md`、`.agent/` | 当前路由、领域语言、硬规则、在飞状态、并行协议 | 会话开始或任务命中时读 |
| L2 冷仓 | `knowledge/` | 为什么、跨对象地图、操作程序、计划、进度、历史、原话 | 从 `knowledge/INDEX.md` 或决策索引按需打开 |

## 一条缝

判断一条事实归哪层，只问：

> 它能不能写成“恰好一个受管理对象”的属性？

- 能：归 L0。prose 最多指认对象，不复述它的契约、约束或行为。
- 不能，但要求系统持续成立：归 `.agent/invariants.md`。
- 不能，且解释跨对象关系或关键数据流：归 `knowledge/system-map.md`。
- 是领域词的含义：归 `CONTEXT.md`。
- 是为什么、备选方案、事故或操作过程：归 L2。
- 只影响当前下一步：归 `.agent/state.md`。

## 热层准入

热层内容必须同时满足：

1. 每次或大多数会话都可能需要；
2. 说的是现在，不是历史；
3. 读到它会改变下一步动作。

不满足任一条，就移到技能正文或冷仓，不要靠“也许有用”留在热层。

## 一条事实一个家

- 规则的唯一正文在 `.agent/invariants.md`；其他地方只放链接或对象级后果。
- 对象认知的操作协议唯一存在于对应技能；规则文件不得写工具命令、分块协议、维护步骤或状态机。
- 冷仓入口是 `knowledge/INDEX.md`；决策先查 `knowledge/decisions-index.md`，永不整篇读 `decisions.md`。
- 决策只追加；改变主意时追加新决策，并在索引中标注旧决策被谁取代。
- 热层和稳定 wiki 不写提交哈希；历史属于 decisions、CHANGELOG、archive。
- 用户原话只增不改；更正通过新 capture 表达。

## 维护

- 代码结构或工作流发生实质变化后，使用 `knowledge-maintain` 判断哪些事实需要搬家。
- 怀疑文档与代码不一致时，使用 `knowledge-verify`，不要凭记忆改结论。
- `scripts/check-knowledge/check_knowledge.py` 检查 prose 与认知层的接线；对象认知与源码是否绑定由对象认知自己的工具验证。两套检查互不替代。
- 事实过期是搬家或标注过期，不是静默删除；archive 保存不再指导今天但解释历史的记录。
